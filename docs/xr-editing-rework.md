# 2026-09-22 — VRの作る・つかむ・飛ばすをつなぐ

## 今回の変更

- 機体を正面の手が届く位置へ。編集パネルは右側へ配置。見出しをつまむ／トリガーでつかむと、パネルだけ移動できる。下の「手元へ呼ぶ」で再配置。
- 手は親指と人差し指の中間位置で模型を保持。機体の各部品の周囲に4.5cmの余裕を設けた。つまむ瞬間の指位置の変化は180msの接触保持で吸収。追跡喪失・解除・退出時に保持を終了。
- VR編集を「形・尾翼の色・音・名前・AI相談」に分け、飛ばす・保存・VR/AR・ブラウザに戻るを常設。ホームに新規作成と保存機体の入口。
- GPTライブとJevは編集画面から接続・開始・停止できる。項目を変えてもAIコンポーネントは維持。AIの案内は編集対象のページを開き、該当ボタンを強調する。会話開始、保存、飛ばすの最終操作は利用者。
- 接続中、操作の反映中、切断を別表示にした。「ready」は操作待ちでもfalseだったため、従来の再接続待ち表示は実際の切断と区別できていなかった。WebSocketの初期部屋情報に12秒の待ち時間を設定。VR内から同じ部屋へ再接続／新しい空で出発できる。
- 自分の機体の出発に、滑走8秒＋上昇・航路への接続25秒を追加。同じ航路サンプルを描画と音の到来計算に使い、共有時刻で同期する。物理的な離陸性能・車輪・帰着を完成させたものではない。
- 部屋がないときの「飛ばす」は8時間の部屋を準備し、飛行受付後に自動飛行を有効にする。部屋・運営画面で繰り返しを停止できる。既存の部屋の設定は飛行時に勝手に変更しない。同時描画・再生は引き続き最大3機、格納庫は24機。多数機同時飛行の実装とは区別する。
- PCの模型周囲をドラッグで回転、Shift＋ドラッグで移動。「飛行中の空」では本当に飛んでいる共有空間を背景に編集できる。編集内容は次の出発へ反映し、飛行中の機体は変えない。
- 小さな操作音と任意の風の環境音を追加。VRの操作音はパネルの位置から再生。主音量・消音に従い、環境音と操作音を個別に切れる。外部音源・有料APIは使用しない。

## 公開入口と移行

入口は https://airplanevoice.pages.dev/ 。Pagesの静的画面と、既存WorkerへのService Bindingで構成する。APIとWebSocketは同じURL配下に保ち、招待URLにも個人名が出ない。旧URLも動作を続け、両URLは同じ部屋に入れる。アカウント全体のworkers.devサブドメインは変更しない。

ブラウザ保存はURLごとに別。旧URLの格納庫から「格納庫を別のURLへ引っ越す」→ファイル保存、新URLで読み込み。名前・機体・音・航路を保持し、同じIDの別機体は上書きしない。AIの接続情報は移さないため、新URLの端末では運営者による接続設定が必要。

公式資料: [Pages Service bindings](https://developers.cloudflare.com/pages/functions/bindings/#service-bindings)、[HTTP forwarding](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/http/)。

公開手順はWorkerを `npx wrangler deploy --keep-vars`、次に `node scripts/prepare-pages.mjs`。`pages` ディレクトリでAccount IDを環境変数に設定し、`npx wrangler pages deploy --project-name airplanevoice --branch main --commit-dirty=true`。ルートのWorker用設定とPages用設定を混ぜない。

## 確認範囲

- Unit196件、ビルド、Worker型検査、Worker dry-runを通過。
- 公開PCフロー、模擬Questの作成・かな入力・保存・呼び出し・出発・AR切り替え・編集中Jev操作を確認。AI応答はfixtureで有料API呼び出しはしていない。
- 指のつまみとパネル移動はIWERのジョイントと入力イベントを使って検証。実機での手の位置の感じ方、文字の読みやすさ、マイク許可、音の聴感はQuestで別途確認する。
- 証拠は `output/xr-rework/`。ブラウザ負荷をかけた並列検証時に既存evolutionテストが一度5秒を超えたが、ブラウザ終了後の再実行は196件成功。チェックの時間制限は緩めていない。
