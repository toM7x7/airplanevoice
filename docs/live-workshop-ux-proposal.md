# 飛ばしながら整える：空間・操作・AIの仕様案

2026-09-22 / 当初の議論案。その後の実装指示により、制作の4手順と共通操作をローカルへ追加した。[現在の実装範囲](creation-experience.md)を優先し、この文書のライブ編集・帰還等は未実装の将来案として読む。公開は保留。

## 体験の中心

「自分の機体を送り出す→見上げて聴く→飛行中に少し変えて比べる→呼び戻す→気に入った状態を残す」。格納庫は保存一覧だけでなく、出発と帰還の場所として見えるようにする。

## 空間

小さな飛行場の観覧場所から、格納庫・誘導路・滑走路・空を一続きに見渡す案。機体は待機→滑走→離陸→周回→帰還→着陸→格納庫へ戻る。見た目の滑らかな動線として構築し、重い飛行物理は追加しない。滑走路の見た目の長さと旅客機の実寸に無理が出ないよう配置し、展示机の寸法に合わせて実寸機体を縮めない。

「戻ってきて」は既定では飛行場へ帰還。「もう一度近くを飛んで」は観覧地点の上空へ再接近。両者は別の操作とする案。頭や手へ飛び込む動作にはしない。

ARでは現在の空と機体の寸法を引き継ぎ、現実を背景にする。格納庫・滑走路は簡素な表示を個別に出せる。机上の縮小模型モードを設ける場合は別途明示し、実寸ARと混同させない。会場への位置合わせは第2段階。

## メニューの入口は3つ

- 機体：名前で選ぶ、飛ばす、呼び戻す、保存する。
- 調整：選んだ一機の音・形・飛び方。初期表示は音。詳細は折り畳む。
- 話す：対話の開始・終了、聞き取り中／返答中、直前の変更を戻す。

全体の音量・VR/AR・操作案内は設定へまとめる。接続状況、部屋管理、会場の位置合わせは運営向けに畳む。未選択時は「調整する機体を選ぶ」と案内する。

| 画面 | 眺めている間 | 調整中 |
|---|---|---|
| PC | 空を広く表示、下部に3つの入口 | 右側に選択機のパネル。音の変更前後を比較 |
| VR | 小さな開閉ボタンのみ | 自分の前に短い操作盤。指操作、音声、コントローラーから同じ操作へ |
| AR | 現実と機体を優先 | VRと同じ操作体系。視界中央を常時塞がず、簡易飛行場表示を選択可 |

「音を調整」では最初は3項目だけ：低い響き／ファンの響き／風の音。内部のbody/fan/airと対応させる。パラメータの値が音量そのものではないことは必要時の短い説明で伝える。

## 飛行中の反映と保存

| 変更 | 提案する反映方法 |
|---|---|
| 音色 | 選択機だけに短いクロスフェードで試す。比較・元に戻すを用意 |
| 機体の色・軽い外観 | その場で試す |
| 胴体・翼・エンジン構成 | 試作中の機体でプレビューし、再生成負荷と不自然な形の変化を避ける適用時点を表示 |
| 帰還・飛び方 | 現在の位置と向きから新しい経路へ滑らかにつなぐ |
| 保存 | 「この状態を保存」で登録値を更新。試している値と保存済みを分離 |

現状の実装は次便への反映が中心。ライブ音色変更・帰還・保存済み機の更新操作は追加実装が必要。共有時は機体ID・変更値・適用時刻・版をサーバーが確定しPCとQuestへ配信。端末自身の音量やメニュー位置は共有しない。

「変えてみよう」は一時的な試聴として即反映できる案。「どうしたらいい？」は提案と対象パネルの表示。「保存して」で確定。毎回確認ダイアログを出さず、変更内容と戻す操作を表示する。複数人が同じ機体を変更した場合は古い版を検知して再取得し、無言で上書きしない。

## AIが受け取るコンテキスト

まずアプリの仮想世界に関する構造化情報を用いる。全映像を常時送る前提にしない。

- 機体ID・名前・位置・進行方向・飛行状態・変更可能な項目。
- 自分からの距離・頭の向き・画角・画面上の方向と大きさ・遮蔽判定ができる範囲。
- 選択した機体、ユーザーの直前の発話と操作、開いているメニュー。
- 自分の場所に到来している音、音の方向・遅延・信号レベル、音色の設定。
- 出発・接近・通過・帰還などの最近の出来事。

頭の向きは眼球視線ではない。視野内にいることと注意を向けていることも区別する。候補が複数なら選択を優先し、「あれ」だけでは対象を断定しない。ARの現実空間の物体や人物は、仮想シーン情報だけからは把握できない。

## 役割分担の案

アプリは正確な状態収集、視野内候補の計算、滑らかな飛行・音生成と操作の検証を担当。
Jevは整理した状況と候補から、注目すべき出来事や調整候補を選ぶ役。
GPT-Liveは会話の窓口として、意図の確認、対象の案内、許された操作の実行と結果説明を担当。

直接指定された「低い響きを少し上げて」はJevの往復を必須にしない。「渋くしたい」のような曖昧な要求や、状況から注目点を選ぶ場面に判断支援を使う。Jevの注目点も常に読み上げず、利用者が質問したときや有用な変化があったときに案内する。

更新頻度はシーン内計算と外部推論を分離。外部には重要変化と間引いた最新状態を渡し、滞留分はまとめる。返答の機体ID・状態版・有効期限を確認し、古い回答を現在の機体へ適用しない。具体的な頻度・料金は接続実装時に決める。今回APIの追加呼び出しはしない。

## 会話例（提案。渋い音の解釈は調整可能）

利用者「この機体、もう少し渋い音にして」
案内「低い響きを増やして、ファンの高い響きを少し抑えてみます」
画面：対象機の名前、該当する2つのつまみを強調。値が変化し、音は滑らかに切り替わる。「元の音と比較」「元に戻す」を表示。
利用者「こっちがいい。保存して」→同じ名前の登録機へ保存し、保存完了を表示。

## 実装順と受入

1. メニューの日本語と3つの入口を整理。対象機・適用先・保存状態が判別できる。
2. 飛行中の音色変更＋比較＋元に戻す。再出発せずに音の違いが聴ける。
3. 簡単な飛行場と出発・帰還。離陸から帰還まで位置や姿勢が飛ばない。
4. 共通の操作へ音声とJev判断支援を接続。音声で行った変更が手操作の画面にも表れ、戻せる。
5. Questで視界・指操作・音・性能を確認。会場案内はこの後。

議論したい一点：観覧場所を滑走路脇とし、離陸・周回・帰還まで見渡せる小さな飛行場の方向でよいか。従来の静かな空だけを見る状態も、メニューや地上表示を閉じて保てる設計にする。


## 追記：VR初回制作を入口にする方向性（コード確認後の移行案）

### PC・VR・ARの位置付け

- PC：制作机と運営席。機体寸法、音、航路の詳細編集、保存、展示の運行を管理。
- VR：AIと自分の一機を作り、送り出して見惚れる体験。初回は形→音→名前→飛ばす。会話と2〜3個の候補ボタンで進める。経験者はスキップして自由調整。
- AR：同じ機体・制作結果を現実の背景で楽しむ見せ方。別の制作アプリにしない。机上模型の制作プレビューと実寸飛行を明示的に区別。会場を案内するARは第2段階。

### 既存コードで流用できる土台

WorkshopRecipeは機体・航路・音設定の共通データ。CreationShelfは名前付き保存、SharedPlaybackは部屋の再生、VrRuntimeとSharedControlSurfaceは空間メニュー・指操作・VR/AR表示を担当。AssistantActionには案内と実行、実行後の結果確認がある。

ただし制作UIはReact画面の状態に寄っているため、そのままVRで表示するだけでは完結しない。制作操作と状態を共通モジュールへ移し、PC・VR・AIをそこへ接続する。現在のAIツールは主に音量、再生、機体選択等で、機体寸法・音色・命名・保存・制作手順の操作は拡張が必要。ブラウザDOMの強調表示もVRの空間パネル用に対応付ける。

### 新しく設ける共通の制作状態

作成中の機体ID、レシピ、名前、チュートリアル段階、直前の値、保存済みとの差分、プレビュー縮尺を管理。AIの会話履歴ではなくアプリが段階を保持する。手操作でも進み、会話終了や応答失敗でも制作を失わない。

「形の候補を選ぶ」「音色を試す」「名前を付ける」「保存」「飛ばす」「戻す」を共通操作にする。GPT-Liveはその操作を呼び、反映を確認して案内する。Jevは曖昧な好みへの候補選択や観察時の注目点を補助する。直接指定の操作まで必ず両AIを経由させない。

### 観覧権限の重要な追加設計

現在、観覧用QRの参加者は共有設定を変更できない。VR制作を成立させるには、参加者自身の下書きで形・音を試し、自分の作品だけを保存・飛行待ちへ追加する範囲の操作を設ける。部屋全体の編集権限は渡さない。展示では端末の利用者交代時に「新しく作る／前の作品を残して終了」を区別する。作品の永続的な個人所有とアカウント方式は未決定。

### 最初の縦につながる実装範囲

1. 制作状態と共通操作を切り出す。
2. VRで形2〜3案→音2〜3案→仮名または命名→保存→既存航路で飛ばす、までを指操作で通す。
3. 同じ操作にGPT-Liveの会話とVR内強調を接続し、Jevの候補選択を必要な場面へ追加。
4. PCの詳細編集と同じレシピで往復し、ARでも体験を継続できることを確認。
5. 飛行中の音調整、飛行場からの離着陸・帰還を段階的に加える。

最初の制作チュートリアルを試すために飛行場の完成を待つ必要はない。完成像には出発と帰還を含める。今回は実現性と設計の確認のみで、チュートリアル機能を実装済みとはしない。
