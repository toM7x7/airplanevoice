# PCで作った空をQuestへ渡す

更新: 2026-09-15 / v0.7.0

機体・航路・機数・開始間隔・周回設定・音の遅延倍率・観察席を、URLにまとめて別端末へ渡せる。受信者が内容を確認して取り込むと、そのブラウザに保存される。飛行開始は端末ごとの操作。複数端末の共通時刻、入室認証、現実空間の位置合わせは後続の開発範囲。

## 試す手順

v0.7.0では[演目](show-workshop.md)全体も渡せる。各機の機体・航路・開始時刻を保持する。単体航路はversion 1、演目はversion 2で共有し、従来URLの読み取りにも対応する。演目のQRを読む端末ではv0.7.0以降を開く。

1. PCで[試遊版](https://tom7x7.github.io/airplanevoice/)を開き、機体や航路を作る。
2. 編集中に「この空をQuestへ渡す」を押す。飛行中なら、編集へ戻ってから開く。気に入った周回は「この航路を残して編集」で残せる。
3. Questのブラウザで共有URLを開く。QRで試す場合は下記のXRQRを利用する。ユーザーのQuest 3で読取と想定範囲の動作を確認済み。
4. 「受け取った空」の内容を確認し、「この空を取り込む」を押す。「今の空を続ける」なら置き換えない。
5. 「VRで空に立つ」から入場し、飛行を開始する。音量と出力先は各端末で調整する。

## XRQRを使う場合

ユーザーから[XRQR](https://xrqr.net/)を候補として受領。2026-09-15に[公式リポジトリ](https://github.com/WebXR-JP/xrqr)と受信処理を確認した。

- QuestのブラウザでXRQRを開き、カメラを許可してPC上のQRを読む。
- XRQRは通常のURL文字列にも対応し、コピー後に「ブラウザで開く」を選べる。SOUND TRAILが生成するQRはこの形式。
- URLを開いた後はSOUND TRAIL側の確認画面から取り込む。
- Quest 3実機で「無事に読み取りはできました」「予定の範囲、想定というラインで動いています」とユーザーから報告を受領。読み取り距離、照明、印刷物での読取、許可画面それぞれの詳細は未記録。読めない場合は「URLをコピー」から別の方法でQuestブラウザへ送る。

自動確認では、実際のXRQRサイトへ生成QRを合成カメラ映像として入力し、復号→URL全文コピー→ブラウザで開く→SOUND TRAILへ取り込む操作が通った。実機カメラの確認とは区別する。

XRQRのサービス・コードをアプリへ内蔵していない。利用案内のリンクを置き、通常のURLで接続する。XRQR側のパスコード機能は今回の共有URLへ付けていない。

## 展示当日に同じQRを繰り返し使う

**現行機能で可能な運用案。会場での反復運用は未検証。** ユーザーから、事前にQRを発行しておき、当日は都度読み込んで入り直す案を受領した。

1. 事前に機体・航路・飛ばし方を確定し、QRと元の共有URLを保存する。QRには演目名や作成日を添えると設定を区別しやすい。
2. 当日は同じQRを読み、「この空を取り込む」→「VRで空に立つ」→飛行開始の順に操作する。飛行中の端末では編集画面へ戻ってから取り込む。
3. 同じQRからは作成時の設定を何度でも開き直せる。使い切り・有効期限の処理はない。途中の飛行時刻へ復帰する機能ではなく、設定を読み込んで各端末で開始する。
4. 機体・航路などを変更して配り直す場合は、新しいQRを発行する。既存QRの内容は自動更新しない。

利用には公開URLへのアクセスと対応する設定形式が必要。会場へ持ち込むQRそのもので当日前に確認する。一度取り込んだ設定が端末に残っていれば、再読み込みから始めることもでき、毎回のQR読取は必須ではない。

複数端末が同じQRを読んでも、開始操作と飛行時計は各端末で独立する。将来のオンライン共有では、QRを固定した部屋URLの入口にし、部屋側から最新設定・共通開始時刻・途中参加の状態を配る方式を検討する。部屋、認証、共通時刻、ARの空間合わせは現行QR機能へ追加済みとは扱わない。

## 保存と制限

- URLは作成時の設定を保持する。後から編集しても既存URLは変化しない。
- 共有した機体・航路と同じ開始条件を再現する。飛行中の時刻、音量、機体選択、カメラ向き、装着位置は引き継がない。
- QRは読み取り密度を抑えるためURL全体1,800文字以内。点が多い航路はURLのみで渡す。2地点生成航路は、完全に再生成できる16点だけを省略してQRを小さくする。自由な描線は点を保持する。
- 取り込み後の再読み込みでも機体・航路・機数・周回・観察席・遅延倍率を復元する。自動で飛行は始めない。端末保存が使えない場合も、その画面では遊べる。
- 初回取得済みアプリの単体オフライン動作と、未取得端末への配信は別。XRQRのオフライン利用は保証しない。

## 実機確認の記録と継続項目

2026-09-15、ユーザーのQuest 3でQR読取と想定範囲の動作を確認。以下の個別条件・感想の詳細は未記録のため、今後の磨き込み時に確認する。

- PCで2地点・2エンジン・3機・周回ありにして渡し、Quest側の表示と飛び方が一致するか。
- XRQRでQRを読み、URLの設定部分まで欠けずに取り込めるか。
- 何もない空のトリガーで選択が外れ、空全体の音に戻るか。
- 線・波紋が機体と視界で重なるときに邪魔にならず、古い軌跡が自然に消えるか。

自動検証と公開結果は[開発記録](../progress.md)、全体の段階は[進捗](progress-overview.md)で管理する。
