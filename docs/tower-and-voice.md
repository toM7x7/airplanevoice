# 管制官と声 — 最初の接続設計

更新: 2026-09-16 / v0.9.1。実装済みの定型案内と、外部AIの候補を分ける。

## 決まった方向

最初のAI役は、ユーザー回答の**「状況を見ながら案内・調整する管制官」**。旅客機の姿とエンジン音を味わう時間を保ち、呼びかけたときに短く相談できる形を優先する。音声サービスの候補は **Aivis Cloud**。OpenAIの最近の音声APIも候補だが、展示で何度も使う費用への懸念がある。採用サービスと予算は未確定。

## v0.9.1で試せる部分

- PCの「管制 / いまの状況と予定」と、VRの「見え方・操作案内 → 状況・案内」。同じ共有時計から、飛行前・飛行中・音の到来待ち・予約便を確認する。
- 飛行中の設定・予約済みの設定・編集下書きを分ける。表示する高度と速度は**設定値**。その瞬間の実測位置・速度や衝突安全性の判定ではない。
- 「状況を読み上げる」で短い**定型案内**。自動発話・マイク入力・LLMは未接続。声は押した端末だけに流れる。
- 端末の日本語音声を使い、利用できないブラウザでは文字を残す。ブラウザ音声は実装によりネットワークを使うことがあり、完全オフラインを保証しない。Aivis Cloudの声ではない。
- 休憩、音量変更、退出、非表示タブ、共有状態の変更、通信断で案内を止める。15秒経過しても終了しない読み上げは破棄。古いカウントダウンや「右」など向きに依存する言葉を音声に含めない。

これはAIの接続前に、状況の正しさと発話・停止のタイミングを試す土台。定型の管制字幕が既にある単体版は従来どおり。

## 接続後の体験案（未実装）

1. 「管制官を呼ぶ」を押す。会話中・残り時間・終了操作を常に表示する。
2. 「次は、もう少し低くゆっくり見たい」と伝える。現在の便と次の予定を渡す。
3. 管制官が短く答え、**次の下書きへの変更案**を出す。現在の便や予約済みの便を勝手に動かさない。
4. 編集者が「この設定を使う」で適用。元の版と異なれば提案を失効させ、既存の値域・航路検証も通す。観覧者は相談・案内まで。
5. 相談終了で音声セッションを閉じる。マイクのミュートだけを終了扱いにしない。

飛行の姿勢・時刻・音の伝播は既存エンジンが担当。AIへの送信は依頼時と必要なイベント時だけにし、毎フレーム送信しない。部屋の鍵・招待URLはモデルに渡さない。複数機の衝突回避、運営権限、実会場への誘導はこの管制官の初回範囲に含めない。

## サービスの違いと費用

2026-09-16に公式資料を確認。金額は料金表のスナップショットで、契約・利用可能モデル・実際の費用は接続時に再確認する。

| 候補 | 役割と課金単位 | この展示で試す用途 |
| --- | --- | --- |
| Aivis Cloud＋別のLLM | 読み上げは従量440円（税込）/1万文字。判断・聞き取りは別途 | キャラクターの声、短い案内。固定文は事前生成と再利用を検討 |
| GPT-Live 1 (`gpt-live-1`) | 音声セッション$0.05/分、秒単位。判断モデル・ツール料金は別 | 聴きながら話し、割り込みや追加の希望にも応じる相談 |
| Realtime 2.1 / mini | 入出力の音声・文字トークンで課金。音声100万tokenあたり標準$32/$64、mini $10/$20（入力/出力） | 一つのモデルで音声対話・判断・ツール選択。実際の会話で測って比較 |
| Workers AI | Freeでは1日10,000 Neuronsまで。アカウント全体で共有、超過は失敗 | テキストの短い提案の候補。日本語品質・応答時間・利用可能モデルは未実測 |

出典：[Aivis Cloud](https://aivis-project.com/cloud-api/)、[OpenAI料金](https://developers.openai.com/api/docs/pricing)、[GPT-Live概要](https://developers.openai.com/api/docs/guides/live)、[Workers AI料金](https://developers.cloudflare.com/workers-ai/platform/pricing/)。Aivisプレミアムは月1,980円（税込）・毎分10リクエスト内で文字数制限なしだが、導入は決めていない。モデルごとの利用条件も確認する。

### GPT-Live 1の試算

| 仮定 | 音声セッション部分の計算 | 小計 |
| --- | --- | --- |
| 1人90秒 × 100人、毎回終了 | 150分 × $0.05 | $7.50 |
| 1台を8時間、接続したまま | 480分 × $0.05 | $24 |
| 4台を各8時間、接続したまま | 1,920分 × $0.05 | $96 |

判断モデル・ツール・税・為替等を含まない計算例。無言やバックエンド待ちもセッション時間に含む。WebRTCのセッション作成では初期化15秒分が課金され、開始後の利用時間分に充当されるため、実行時間に一律15秒を加算しない。接続失敗や頻繁な再接続も測定に含める。[公式の課金・最適化](https://developers.openai.com/api/docs/guides/voice-latency-cost?api=live)

Realtimeは接続時間そのものではなく応答ごとのトークン課金。GPT-Liveの計算式を流用しない。会話履歴の再入力、キャッシュ、文字起こしの追加料金を含め、APIが返すusageを記録する。同じ100人でも会話量で変わるため、この段階で総額を断定しない。[Realtimeの課金](https://developers.openai.com/api/docs/guides/voice-latency-cost?api=realtime)

**比較の仮説**：短い相談ならGPT-Liveも候補に残る。固定案内を何度も流す用途なら、事前に作った音声を再生する方式を先に比較する。Aivisの音声生成費だけで、音声対話全体が安いとは判断しない。

## 費用を制御して試す順序（未実装）

1. まず利用予算・モデル・声を決め、秘密鍵をサーバーに設定する。ブラウザやQRへAPIキーを入れない。
2. 例として1回90秒・同時1会話・1日20回など、小さい上限で10会話を評価。数値は候補であり、ユーザーの予算承認ではない。
3. サーバーが枠を先に確保し、終了・タイムアウト・切断時に会話を閉じる。クライアント側タイマーだけに依存しない。日次予算に達したら新しい会話を開始しない。
4. 最初の応答が聞こえるまでの時間、意図した設定が作れた割合、割り込み停止、1会話の音声＋判断費用を記録する。APIの音声生成開始時間と、アプリ全体の会話遅延を分ける。
5. 展示音・周囲の声があるQuest本体スピーカーで、聞き取りとエンジン音の邪魔にならないかを実機評価する。

自動案内は、通過の見どころでは黙る・古い出来事を話さない・複数端末で重複生成しない、を満たしてから追加する。途中応答・提案・適用結果は別の状態として扱う。

## 今回の見直しと次の境界

| 責務 | 現在の場所 | 次に守る境界 |
| --- | --- | --- |
| 共有と飛行の正本 | `shared-room.ts` / `room-worker.ts` | LLMの出力で直接上書きしない。保存・版・権限はサーバーが判定 |
| 描画・位置音の進行 | `shared-playback.ts` / `Scene.tsx` / `audio.ts` | 音声対話が遅れても飛行を止めない |
| QRの生成・役割別招待 | `RoomInvite.tsx`へ分離 | 来場者／編集者の鍵を混同せず、非同期生成の古い結果を破棄 |
| VRメニュー | `shared-panel.ts`へ分離 | 既存操作の押す場所を保ち、PCと同じ操作へ渡す |
| 管制が参照する事実 | `room-observation.ts`へ分離 | 現在便・予約便・下書き・接続状態を区別 |
| 発話と停止 | `room-speech.ts`へ分離 | プロバイダーを交換しても休憩・期限・中断を守る |

単体の`App.tsx`、XRの機器制御、描画の負荷最適化は次の見直し単位。今回の分離をプロジェクト全体のリファクタリング完了とは扱わない。
