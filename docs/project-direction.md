# SOUND TRAIL — プロジェクトの方向

更新: 2026-09-17 / v0.11.0。最新の体験の構成・優先順は[体験・エンジンの再設計](experience-redesign.md)を参照。以下の版番号付き記述は経緯も含む。

この文書を、会話と試作から更新する現行方針とする。3冊のWordは原点を保存する基礎資料。資料内の指示例や初期案が、後から合意した方針を上書きすることはない。

追加の31分類キーワード棚卸しも構想資料として受領。[索引と発想メモ](idea-atlas.md)を参照し、採用前の案と現行方針を区別する。

## 作りたい体験

**地上で旅客機を待ち、巨大で重い機体が滑らかに通り過ぎる姿を見上げ、遅れて届く音を聴く。その空を、隣の人とそれぞれの視点から共有する。**

空を眺める余白、旅客機の存在感、あとから届くエンジン音を中核にする。音から機体を探す楽しさと、姿を見つけてから音を待つ体験を両方育てる。独立したWebサービスとして、必要な表現・エンジン・操作を選ぶ。

### 品質目標：「見惚れる」

2026-09-16、ユーザーが「見惚れる」を大事な品質目標として確認し、企画整理の後にコードでの改善を依頼。[見惚れる飛行の仕様・実装記録 v0.2](absorbing-flight.md)へ、光・形・空・音の候補と比較手順を整理。v0.8.1では光・材質・機体形状をコードで改善し、PCで比較した。通常の観察距離とQuest実機で「見惚れる」品質が届くかは継続評価する。

## 2026-09-17の整理

仮想の空・展示会場・将来の空港の3世界をVR／ARで見る6通り。まず仮想と会場の4通りを育てる。小さな地図と実寸表示は同じ会場座標の見方として扱い、耳や飛行の単位は変えない。v0.11.0では会場地点の縮小配置図と実寸表示の選択を追加した。実際の図面、ブース間飛行、MCP／LLMは後続。

直近は固定机でQuest 3＋Quest 2の位置合わせを実測し、実際の会場図＋3ブースの手動案内へ広げる。同時に機体・飛行・音・軌跡を同条件で磨く。[優先順と完了条件](experience-redesign.md#8-次に進める順序と完了条件)で管理する。

## 2026-09-16の方向修正（経緯）

**追記: 次の優先は、PC＋Questがクラウドの同じ部屋に入り、両方から作って飛ばすマルチ操作。** ユーザーが初回構成を「PC＋Questで、両方から操作」と回答。ドームやLLMを先行条件にせず、共有編集と同期飛行の設計へ進む。[初回構成と設計案](shared-sky.md)。

- ユーザーから、演目を作る方向が本来の企画から離れつつあり、作る行為自体も複雑だとの指摘を受領。旅客機が飛ぶ姿を見届ける体験を中心に戻す。
- 機体・航路を作る自由は残す設計とし、細かな設定を組み上げることを初回体験の必須条件にしない。既存の演目データ・編集機能は補助として位置づけ直す。画面の変更方法や機能の撤去は今回決めていない。
- ミニチュアの空から地点を選び、その場所の音・視点を体験するドーム／ミュージアム案を受領。地上で見上げる原点を広げる候補として検討し、まだ実装要件にはしない。
- LLMへ見たい飛行の要件を渡すこと、パイロット役・管制官役も検討候補。入力の手間を引き受ける役と、飛行の意図・調整を担う役を分けて考える。役ごとに別モデルや常時会話が必要とは決めない。

v0.8.0ではCloudflare Freeで共有ルームを追加した。従来の単体版とは入口を分け、両方から編集・発進・次便の予約を行う。[共有設計と範囲](shared-sky.md)。新案の詳細は[思いつきメモ](idea-notes.md)、AIの分担は[作る体験とAI](creation-and-ai.md)へ。

## ユーザーと確認済みの方向

| 決定 | 開発への反映 |
| --- | --- |
| 独自サービス・単体検証として作る | XRiftの制約、連携、移行互換性を前提にしない |
| Wordを基礎に、別の資料も更新しながら作る | 本書で現行方針を管理。原本は編集しない |
| 音の方向が気になり、向く瞬間が楽しかった | この発見を、説明や演出の量を決める基準にする |
| 複数端末で同じ空を作って飛ばす。初回はPC＋Questで両方から操作 | 共有編集・共通時計・観測者別音響。PC専用編集／VR専用観察に固定しない |
| 飛び方の成立と機体同士の調整は各エンジンが担う | LLMは提案と意図の入力を担当。生成待ちで飛行や手動操作を止めない。衝突回避は未実装 |
| AIは管制官のような案内・調整役 | 飛行の受付、予定・状況の案内、順番の提案を扱う |
| AR、機体・音・空の磨き込みに期待 | WebXR実機試作と、体験の質の改善を継続する |
| ARは機体を現実に重ねる基本モードと展示会案内の2系統 | [AR設計](ar-modes.md)に記録。会場の測量・校正は管理操作として区別し、MCPによる案内は後続候補 |
| 機体を作る・航路を作る・飛ばして観察する | 画面操作とJSONを共通のレシピにする |
| 重さや慣性が感じられる滑らかな飛び方 | まず傾きがゆっくり追従する表現を試す |
| v0.7.0後、演目づくりを中心に据える方向を見直す | 独立設定・保存の土台を活用しつつ、地上から旅客機を見上げる体験を優先。操作の再設計は未実装 |
| 旅客機らしい、重く厚みのある響き | 高域のノイズを丸め、低〜中域とファン成分を重ねた双発／四発の合成音へ |
| 通常はクラウド、会場からネットで接続 | 単体版はGitHub Pages、共有試作は指定アカウントのCloudflare Free。独自ドメインは取らない。長期運用の基盤は別途相談 |
| ローカルはフォールバック | 単体のオフライン再開を用意。ローカルAIは接続方法の設計に留める |
| 思いつきは実装とは別軸で残す | [思いつきメモ](idea-notes.md)へ蓄積し、採用前の案を実装予定に数えない |
| 機体を選び、速度・方向を情報として見たい | 読み取り専用の機体情報を表示。音の注目機とは別に選ぶ |
| 進捗を段階・何分の何で整理したい | [進捗と段階](progress-overview.md)で全体6段階と各段階の確認項目を管理 |
| 周回ごとに航路が変わり、自動で飛び続ける | 全機の音到来後に次の航路を生成。気に入った周回を保存できるようにする |
| 条件によって動的に変化する。まずPC中心 | [条件から変わり続ける飛行](procedural-flight.md)に現行条件と天候・他機などの発展先を分けて記録 |

「任意のところから離発着する」は発展させたい候補として記録する。地点を決める操作、必要な空間、離発着の表現は未確定。Blenderを使った部品制作、リアルタイム解説、QRでの入室も具体化候補。

## 現在触れるもの（v0.11.0）

- PC＋VRの共有編集・同期飛行・招待URL／QR・次便の予約・切断復帰。共有版は1機＋次便の予約。通常1時間／展示8時間の部屋、観覧QR、AR切り替え、手動位置合わせ、会場地点の共有と縮小図を利用できる。会場図画像・専用管理権限・LLMは未接続。

- 最大3機の独立した機体・航路・開始時刻と、演目単位の保存・JSON・URL／QR。観測図には最接近と音到来の予測・履歴を表示する。実装済みの範囲は[操作資料](show-workshop.md)を参照。今後の中心体験として演目作成を確定した意味ではない。

- Quest 3で地上から見上げる1人用VR。頭に追従する音、空間操作盤、機体選択・解除。3機の聴取と明示的な解除を実機確認済み。
- PCで作った空をURL／QRへまとめ、Quest側で確認して取り込む。[受け渡し手順](sky-transfer.md)。XRQRは読み取りの入口候補として案内する。
- 機体との視界上の重なりで線・波紋を薄くし、古い音航跡も透明度で消す。何もない空をクリック／トリガーで選択解除できる。

- 「つくる実験室」で胴体・翼・エンジン数を変え、空で見る。
- A/Bの2地点、幅、高度、速度、シード、ゆらぎから航路を作る。離発着ではなく空中の通過点。
- 傾きの追従時間を調整し、曲がり方の印象を比べる。
- JSONレシピを編集・適用・書き出し。機体と航路は端末に保存する。
- 公開版を初回取得した後は、通信が切れても単体体験を再開する。

- PCブラウザで1〜3機を飛ばす。開始間隔は同時・8秒・16秒。
- 同じ編集航路をもとに、追加機は位置をずらした比較用航路を飛ぶ。
- 注目する1機を聴く／空全体を聴く。ほかの機体の音を残しながら、注目機を切り替える。
- オプションの管制字幕。準備、飛行開始、最初の音の到来、周回終了、全体終了を案内する。
- 各機の音到来が終わるまで待ってから、次の周回へ進む。
- 空の機体や「機体情報」から1機を選び、速度・進行方向・高さ・距離を見る。その瞬間の機体の方へ地上から視線を向ける。
- 周回ごとに航路を変えて自動継続する。変化の幅を選び、気に入った周回を残して編集する。飛行中の主航路とST-01の位置を小さな図で見る。

管制字幕は**定型文によるローカル実装**。外部AI、操縦指示、衝突回避は未接続。共有版には別途、部屋の事実から作る定型文と端末の読み上げを実装済み。ここでの最大3機は単体版の範囲で、共有版の1機＋予約1便とは区別する。

## 独自エンジンを育てる単位

音の分布レイヤー、観察するAIの視点切り替え、録画ファイルの予備再生は[思いつきメモ](idea-notes.md)へ保存した。

描画ライブラリやブラウザの標準機能を使いつつ、体験固有の判断と計算を自分たちのコードに持つ。詳細は[エンジン設計](engine-design.md)。

| 単位 | 担うこと | 現在 |
| --- | --- | --- |
| 航路・飛行 | 描いた線を解釈し、時刻から機体の姿勢を決める | 実装済み |
| 空域・運行 | 機体、航路、飛行開始時刻、進行状態をまとめる | 単体3機、共有1機＋予約1便 |
| 音伝播 | 過去の発音点から、観測者に音が届く時刻を計算 | 近似モデルを実装 |
| 聴き方 | 機体別の響き、音の密度、聴取対象を調整 | 注目／全体を実装 |
| 管制・解説 | 状況の案内、飛行順の提案、音を聴く時間への配慮 | 定型字幕、共有版の状況と端末読み上げ |
| 機体・空の表現 | 機体部品、材質、光、雲、距離感 | 寸法・配置を変える仮メッシュ、反復部品の一括描画、遠距離の細部省略 |
| 共有空間 | 部屋、共通時刻、参加・復帰、空間の位置合わせ | 共有ルーム・共通時計・復帰を実装。手動座標合わせを追加。Quest 3＋2の実測はこれから |

空の表現や機体制作は、必要が出た時点で切り出す。まだ使わないエンジンの空フォルダは設けない。

## 次の段階と確かめること

以下の6段階は開発の到達点の分類として保つ。体験の6通りとは分け、直近の優先順は再設計書で更新する。共有飛行は実装済み。会場の縮小図を追加したが、地点による耳・視点の移動とドームは未実装。各段階の状態と確認項目数は[進捗と段階](progress-overview.md)を参照。

1. **作って、飛ばして、また変える。** v0.3の機体・2地点航路・レシピで、この往復が楽しいかを試す。追従時間で重さを感じるか、同時／時間差・注目／全体でも「どっちにいる？」が残るかを確認。公開URLと単体の予備動作を検証する。
2. **1台のQuestで、その空に立つ。** 独立WebXR、頭の向きに追従する音、実機フレーム時間を確認。HTTPSの検証環境を用意し、VRから始めてARの支持機能を実機確認する。
3. **2台で同じ飛行を見る。** 部屋と共通時刻を導入。途中参加でも同じ機体を同じ時刻の位置に出す。音は各自の観測位置で別々に届く。切断・復帰を試す。

   その前段として、ユーザーが「PCで作った機体・航路をURL／QRでQuestへ渡して試す」を選択。v0.6.0で設定受け渡しを実装する。これは第2段階から第3段階へ進むための土台で、同期飛行の完成には数えない。
4. **現実の場所に、その空を重ねる。** QRによる同じ部屋への入口と、現実空間の原点・向き合わせを別々に検証。QRを読んだだけで空間が一致したとは扱わない。同室／遠隔の共有方式もここで選ぶ。
5. **飛ばし方を管制官と相談する。** 任意地点からの離発着、離発着順序、混雑への提案を検証。LLMは構造化した提案を出し、飛行エンジンが条件を確認して採用する。
6. **展示・継続運営の準備を整える。** 保存・必要な利用集計・費用・会場での復旧を確かめ、本番基盤を選ぶ。段階1のGitHub Pages公開は試遊用の到達点とする。

機体の存在感、エンジンの音色、空の光は段階1以降も並行して磨く。最初の品質改善候補は、通過時の音の層、翼の陰影、近景と遠景の距離感。Blender導入は、メッシュや部品の制作目的が定まってから判断する。

## 管制官AIの役割

- 「どこから、どちらへ飛ばしたいか」を受け取り、飛行案にする。
- 現在の飛行予定を読み、次の開始時刻や順番を提案する。
- 見えている／聞こえている出来事を、実際のイベントに基づいて短く案内する。
- 音を聴く場面では発話を控える。実況の連続発話を前提にしない。

飛行位置を毎フレームAIで計算しない。AIの返答が遅れても、飛行と音の時刻は進む。返答には対象の便、予定の版、適用できる時刻を付け、古い案内や変更案は採用しない。これは今後の設計方針であり、現行の字幕にLLMの判断は含まれていない。

## 多くの機体が飛ぶときの考え方

1. **共有する予定で調整** — 開始間隔、飛行経路、同時飛行数。全員が見る空に反映される。
2. **各自の聴き方で調整** — 注目機、距離減衰、音量配分、同時発音数。ほかの参加者の設定を変更しない。
3. **管制案内で調整** — 次の発進を提案する／近接通過中は話さない。

「音を減らすほどよい」とは決めない。遠くの機体に気づける程度の背景音は残す。現在の最大3機と音量配分は、初回比較の値であり、完成仕様ではない。

## まだ決めないこと

- 当面は固定机を囲むQuest 3＋Quest 2。これを超える同時人数・対応機種は未決定。[2台の位置合わせ](table-alignment.md)を先に実測する。
- AIモデル・サービス・音声合成・課金方式。
- 恒久保存・利用分析・長期運用の費用。共有版はCloudflare Freeへ公開済み、単体版はGitHub Pagesを使用し、[本番環境の相談](production-options.md)でCloudflare・Vercel等を比較する。
- 離発着時の入力、空港の再現度、飛行性能の精度。

その段階の試作に必要になった時点で、選択肢と実機結果をもとに決める。
