# 操作部品の試作 — バーから開いて、空へ戻る

2026-09-17 / **ローカルの動作試作。公開版の操作盤への適用前。外部AIは未接続。**

**2026-09-18の位置づけ：** 上記と以下の実装記録は操作部品の試作を指す。通常ブラウザ画面には別途AI操作を接続済みだが、この空間内メニューへのAI接続は未完。[声・クリック・指操作の体験仕様](ai-guide-spec.md)の第0節で、目的別メニューと「対象を表示→1つ強調→実操作で完了」を次の改善案として整理した。今回の更新は仕様のみ。

ユーザーから、バーを選ぶと「フオン」とメニューが開き、選ぶ・閉じると引っ込む動き、意図が分かるアイコンと日本語、部品を組み合わせる構成を提案された。画像案の配色を使い、PCと空間内で実際に操作できる部品へ進めた。

## 試す入口

**2026-09-18 操作アシストの予行を追加：** PCで「操作案内を試す」を押すと、音量を変える手順を1つずつ表示する。押す場所に枠と「ここ」が付き、本人の操作で値が変わると完了。別のページを開いた場合も現在の画面から案内し直す。「案内をやめる」または2分で終了。音の再生開始と音量設定を区別する。API接続前の定型ガイドで、GPT-Liveの発話・TypeSafe観察は未接続。XRへ入るとこの練習は終了する。[実装先・UI確認](ai-implementation-plan.md)

**2026-09-18再更新：** ユーザー評価を受け、実際の操作盤は短く静かな開閉へ変更。開く180ms／閉じる120ms、最大8pxの移動とフェードのみ。機影・波紋・回転・項目の段階表示を外し、比較用の選択パネルも撤去。公開版への適用前。過去の3案と映像は比較履歴として保存する。

`npm run dev` → PCで **http://127.0.0.1:5173/?ui=components** を開く。

1. 下の「メニュー」を押す。
2. 「飛ばして眺める」で旅客機を飛ばす。メニューが閉じ、飛行が続く。
3. 「音を聴く」でエンジン音を開始。「聴き方」で音量を変える。
4. 「見え方」「操作案内」を開き、戻る・閉じる・再び開くを試す。

PCではEscや空のクリックで閉じる。キーボードではTab・Enterでも操作でき、閉じたメニューの項目にはフォーカスが入らない。OSの動きを減らす設定を初期値に使い、「見え方」でも変更できる。

QuestではHTTPS上に配置した同じ入口を使う。今回のローカルURLはPC用で、QuestからこのPCの`127.0.0.1`へは接続できない。**今回のQuest確認はIWERによる模擬操作。実機向けの公開反映はまだ行っていない。**

空間内ではバーを選んで開く。手入力時はピンチ／指先タッチ、コントローラー時はトリガーを使う。操作盤は空間に置かれ、頭へ貼り付かない。グリップで正面に呼び戻す。AR対応の入場なら「見え方 → 現実に重ねる」で既存の背景切り替えを利用できる。背景自体を透過アニメーションにする案は後続。

## 今回できた部品

| 部品 | 役割 | 実装 |
| --- | --- | --- |
| 操作の定義 | 操作ID・日本語・アイコン・短い説明・使えない理由・影響範囲を持つ | `ui/control-menu.ts` |
| アイコン付きボタン | 押せる／押せない状態を示し、日本語も必ず添える | `ui/ControlDock.tsx` |
| 小さなバー | メニュー、音、選択解除をまとめる | `ControlDock` |
| 開閉メニュー | まず4項目。聴き方・見え方・案内へ進む | `ControlMenuState`と`controlMenuView` |
| 開閉の動き | 開く180ms、閉じる120ms。8px以下の移動と短いフェード | PCはCSS、XRは`DisclosureMotion` |
| 空間内の描画 | 同じ操作定義を3Dの板へ描画。見えている位置で当たり判定する | `SpatialControlMenu` |

開閉に効果音を追加しない。世界観は配色、余白、細い線、アイコンと押した反応で表現する。飛行と位置音を主役にし、項目の再配置やカメラ移動を行わない。旧比較画面と映像は未採用案の履歴。

連打に対してアニメーションを順番待ちにせず、最新の開閉指定へ向かう。閉じ始めたメニューの項目はすぐ操作不能になる。XRでは透明な余白が機体の選択を遮らず、消えたボタンが押されないようにした。

## AIとつなげる位置

最初の候補は、**「操作案内」を必要なときに開き、今の状況に合う案内を受ける**流れ。たとえば「音を大きくしたい」なら、`menu.sound` → `sound.louder`の操作を案内する。日本語の文字列や画面座標を推測して押す構成にしない。

1. **案内**：いま使える操作と状態を読み、該当するボタンを言葉で説明する。今回の案内文は固定文。
2. **指し示す**：操作IDから対応するPC／XRのボタンを強調する。これは後続の部品。
3. **操作を手伝う**：ユーザーの依頼を同じ検証済みの操作へ渡す。実行前に現在の可否を再確認し、結果・失敗・取り消せる範囲を表示する。AIによる実行入口は今回追加していない。

共有版へ適用するときは、この端末の音量と、部屋全体の飛行開始・会場配置の編集を区別する。現時点の試作はすべて自分だけの操作。今回の`scope: device`を共有操作へそのまま流用しない。観覧権限・サーバー検証も継続する。

## 現行アプリとの関係

- `?ui=components`だけに表示する。通常の単体版・共有版の操作盤を一括で置き換えていない。
- `Scene`・`Experience`・音・XRの既存エンジンを利用する。保存済みの機体・航路を読み書きせず、部屋APIへも接続しない。
- `VrRuntime.controlSurface`に任意の操作面を接続する拡張を追加。未指定時は従来の描画・入力の経路を使う。
- 開閉の処理で飛行・耳・共有時刻を操作しない。XRを非表示にした場合や退出した場合の音の休憩は、既存のライフサイクルに従う。
- メニューのアニメーションと、[VR／ARの背景トランジション](visual-transitions.md)は別の実装単位。

## 次の判断
