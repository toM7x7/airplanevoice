# 会場に依存しないVR・ARの基礎とJevの役割

## 2026-09-21 確定した品質目標と順番

**一機を見て・聴いて見惚れる → みんなが作った機体が飛び交う → 会場マッピング。** 制作とJevによる判断支援は、この体験を支える機能として育てる。

リアリティの目標は寸法・距離感・大きさ感、そして頭上を通過する存在感。厳密な飛行性能・空力計算は不要。音の品質は優先し、合成エンジンで旅客機らしい低い厚み、ファン、気流、接近と通過を磨く。実際の耳元音圧の保証とは区別する。

- **制作の主画面はPCのブラウザ**：航路・機体・音の編集、試聴・比較、名前付き保存を中心にする。名前付き保存・読込・部屋への登録は今回ローカル実装済み。
- **Questは観察と軽い調整**：呼び出し・選択・試す・音量等を分かりやすくする。編集機能を排除はしないが、全制作操作をQuestへ同時に載せることは必須にしない。端末負荷と操作の負担をそれぞれ検証する。
- **Jevは観察と制作の両方を支援**：ユーザーのカメラ方向・視野内候補・音・操作履歴を継続的に更新し、注目点や多いパラメータからの候補選択に活かす。実際の眼球視線とは区別する。対話AIは選択の理由や次に試すことを説明する。
- **常に観察しても、常に話さない**：見惚れる時間を邪魔しない。「聞かれたら答える」「意味のある変化だけ知らせる」「静かに観察する」を選べる仕様にする。計算・描画を外部AIの応答待ちにしない。
- **みんなの空**：一機の品質が整った後、各自が作って名前を付けた機体・音・航路を持ち寄り、同じ空で眺める。保存する機体数と同時に描画・発音する数は別に設計する。複数Questは必要条件にしない。

### 最初の基準フライトの受入

1. 接近→頭上またはすぐ脇を通過→遠ざかるまで、一機で体験できる。
2. 寸法を途中で変えず、ユーザー位置からの水平距離と高さで見かけの大きさが自然に変わる。
3. 顔を上げたとき翼や胴体を見渡せ、視点が機体内部へ入らない。
4. 頭の向きに応じて音の方向が変わり、接近・通過・余韻が聴き分けられる。実音圧の再現は要求しない。
5. 同じ条件で繰り返し、航路・機体・音を一項目ずつ変えて比較できる。

既存の「正面のフライバイ」は使える土台だが、任意のユーザー位置の頭上通過を保証していない。今回、地上原点の約220m上を通る航路の準備を実装。最終的にコンパイルされた航路の水平接近距離5m以内を検査する。移動したQuestの現在位置へ自動追従する機能ではない。公開は認証切替待ち。

2026-09-21 / コード・生成ジオメトリの監査と次段階の設計。今回、公開アプリの挙動は変更しない。

## 最新の優先順位

会場マッピングを次点にし、Quest 3単体で旅客機を見上げ、音を聴き、機体・航路・音を作って変化を楽しめる基礎を先に整える。PCからの共同操作は維持する。ユーザーの「ジェブ／JV」はTypeSafeのJev。Jevの判断を対話アシスタントの有用性にも結び付ける。

## 寸法監査の結果

| 項目 | 現在のコード・計測値 | 判断 |
| --- | --- | --- |
| 座標 | m単位。XRのrigに拡大縮小なし | 実寸の土台がある。実機の床・追跡設定は別途確認 |
| PC初期視点 | 草原は高さ1.7 m。丘の上は別の観察地点 | 全利用者の身長を1.7 mにする設計ではない |
| XR視点 | local-floorの頭の位置を使用し、位置合わせ時は剛体変換 | 立位・座位の頭の高さを使用。固定の人型モデルはない |
| 標準機 | 生成メッシュの胴体71 m、主翼の左右端64 m | 747-400級の寸法。特定の実機の精密復元ではない |
| 制作設定 | 胴体50〜85 m、翼幅45〜85 m、2/4発 | まだ大型機中心。小型機まで選べる機種体系ではない |
| 高度 | 制作の既定値240 m、設定範囲140〜500 m。生成時に上下変化あり | 仮想平面の高さ。全地形との対地高度・飛行手順を保証していない |
| 速度 | 58 m/s（208.8 km/h）、制作範囲35〜75 m/s | コードにも観察用速度と明記。重量・揚力・失速等と整合させた性能モデルではない |
| 音 | 伝搬・距離・方向を扱う合成音、本体スピーカー用補正あり | 信号dBは実際の耳元音圧dB SPLではない。物理的な音量再現を保証しない |

比較資料：Lufthansaの747-400諸元は全長70.66 m、翼幅64.44 m。[公式機材情報](https://www.lufthansa.com/gb/en/74e.solo_continue)

実測手順は生成ジオメトリのBoundingBoxを計算。`output/scale-audit/2026-09-21.json`へ記録した。標準制作設定の生成点を草原視点から測ると約568〜2291 m。これはコンパイル前の生成点群で、現在の保存ルームや最終曲線の測定ではない。翼を正対させた64 m幅の見かけ角の目安は約6.45〜1.60度。高度だけでは大きさの感じ方は決まらず、水平距離・視野角・向き・比較物も効く。

## 実寸と手元模型

- 実寸観察：1:1。ユーザーに近づいても機体の物理寸法を変えない。旅客機らしい距離と通過速度を設計する。
- 手元模型：別の表示として、地形・航路・機体を同じ縮尺で縮小する。例えば1:1000なら全長71 mは7.1 cm。縮尺と「模型」の表示を出す。表示範囲に合わせた縮尺調整は可能。
- 縮小するのは表示用の複製。飛行計算の世界座標はmのまま維持する。選択IDで模型と実機表示を対応付ける。
- 音の聴取位置は明示する。「地上の観察地点で聴く」か「模型上で指定した地点で聴く」を選ぶ。模型の数cmの距離を実寸エンジン音の減衰計算へ混ぜない。
- 現在の会場縮小図は地点の配置図であり、この飛行機付き模型と聴取地点選択は未実装。

## 観察コンテキストの基礎

アプリが継続的に更新する現在状態と短い出来事の履歴を共通化する。描画・音響の各フレームを外部AIへ送る構成にはしない。

| 収集する事実 | 用途・注意 |
| --- | --- |
| 観察位置、カメラの向き、投影範囲、VR/AR、実寸/模型 | 視野内候補を幾何計算。頭・カメラの向きは眼球視線や興味の断定ではない |
| 機体ID・寸法・位置・速度・方位・バンク角 | 対話時に「あの機体」を解決する候補 |
| 距離、接近/遠ざかり、予測最接近、視野内/外、必要なら遮蔽 | 見えていない機体を見えていると案内しない。画面内判定と遮蔽判定を分ける |
| 鳴っている音、信号レベル、到来方向、伝搬遅延、ユーザー音量 | 「姿は前方、音は後ろ」という本企画の特徴の説明 |
| 選択機体、直近の操作、編集画面、変更前後のパラメータ | 同じ解説の連発を避け、制作相談に関係する情報を選ぶ |
| 天候・風・空力等 | 未実装の条件は不明／未計算とする。推測を実測値として渡さない |

現行の`skyContext`は機体の状態、距離、半径方向速度、信号dB、UI状態を渡している。視野、姿勢、全環境情報の統合は未接続。カメラ画像を送る前に、仮想世界から取得できる構造化状態を使う。現実の会場映像の収集は今回の対象にしない。

## Jevをエンジンと対話へ入れる

Jevは状態に対してChoice/Score/Noulで判断を返すモデル。自由な解説文や3Dメッシュ、音声波形を直接生成する役として扱わない。[公式仕様](https://docs.typesafe.ai/introduction)

`エンジンの事実 → 観察コンテキスト → Jevの候補選択・評価 → 対話AIの説明／変更プレビュー → 採用した設定をエンジンへ`

- 観察：「今、どの機体の何を説明すると役立つか」「今は黙っているべきか」。距離・衝突予測の数値自体はコードで計算する。
- 航路：「もっと近くで翼を見たい」から、成立を検査した高度・旋回・通過方向の候補を選ぶ。
- 機体：「大きくゆったりした感じ」から、用意した寸法・翼・エンジン配置の候補を評価する。
- 音：「厚みはほしいがうるさくしたくない」から、低域・ファン・気流の音設定候補を選ぶ。音量と音色を分ける。
- 変更案は同じフライトで比較し、採用／元に戻すを可能にする。手動操作と同じ設定検証を通す。
- 誤判断・古い状態・応答遅延はあり得る。状態の版と対象IDを照合し、遅れた結果で新しい手操作を上書きしない。APIが応答しなくても飛行・音・編集は継続する。

## 次の小さな完成単位

1. **実寸の基準フライト**：一機が接近→側面を見せて通過→遠ざかる。視点高さ・距離・速度・寸法を確認できる。目と耳の違いを観察する。
2. **一つ変えて飛ばし直す制作**：航路、機体、音を一項目ずつ変え、同条件で比較・戻す。機体数の増加は基準フライトの品質確認後に進める。
3. **観察から役立つ一言**：共有コンテキストを画面で検証し、Jevの注目点と対話の説明を接続する。まずは「左奥の機体が近づいています」等の検証できる内容。

今回の成果は寸法の検証とこの再設計。上記3段階の新機能、Jevへの追加送信、手元模型の飛行機表示は未実装。公開変更・有料API呼び出しは行っていない。
