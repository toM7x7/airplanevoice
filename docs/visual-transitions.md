# AIRPLANEVOICE — 入口とVR／AR切り替えの画面案

2026-09-17 / **将来の磨き込みを考える資料。演出は未実装、最終デザインは未決定。**

ユーザーの「先にやることではないが、入口・切り替えにも飛行機や音らしさを入れたい」という発想を、画像と動きの候補にした。現在の優先順位（Quest 3＋Quest 2の実空間での位置合わせ、仮想／展示会場のVR・ARの基礎）は変えない。公開アプリはv0.11.0のまま。

## 1. おすすめの方向

続く相談を受け、バーと開閉メニューを[操作部品の試作](control-components.md)へ進めた。PCと空間内で使えるローカル試作で、下の画像をそのまま公開版へ置き換えたものではない。VR／ARの背景フェードは引き続き構想段階。

**機体とエンジン音がつながったまま、仮想の風景が静かに透け、現実の部屋が現れる。**

旅客機を見惚れて眺める時間を中心にする。白い機体の幅のある反射、薄い雲、低い地平線を使い、操作を終えると視界が空へ戻る。入口や選択には細い誘導線と短い音の余韻を添える。

現行のアイボリーと深緑を引き継ぐ。候補色はアイボリー `#f4f2e8`、深緑 `#173f45`、淡いミント `#c3e5e0`。選択箇所に少量の真鍮色を使う。機体・背景・文字の見やすさを実機で確認してから調整する。

## 3. 動きの候補

時間は実装後に試す仮値。静止画では滑らかさ・実機負荷・パススルーの見え方を判断できない。

### 入口 → 空を見る

- 「空に入る」を押すと、ボタンの細い線が短く伸びる。接続待ちは実際の状態を文で示す。演出の進み具合を通信の完了率には使わない。
- XRへの入場と初期表示が成立してから、案内が0.2秒程度で退き、空の表示が落ち着く。ブラウザの許可操作は実際の手順として残す。
- 頭や視点を自動で移動させない。開始時から見上げられ、操作を急がなくても機体を探せる。

### 仮想背景 → 現実に重ねる

| 時間の候補 | 見え方 | 続けるもの |
| --- | --- | --- |
| 0〜0.15秒 | 押した項目だけを穏やかに強調 | 飛行・頭の追跡・耳・共有時刻 |
| 0〜0.9秒 | 空・地面・木などの仮想背景が徐々に透ける。霧も合わせて弱める | 同じ機体の位置・姿勢・大きさ・照明 |
| 終了時 | 現実の背景と機体を表示。「空に戻る」を選べる | エンジン音、選択状態、端末の校正 |

逆方向は仮想背景が静かに現れる。往復で機体を再生成せず、音源を再起動しない。各人の切り替えを部屋全体へ強制しない。

**最初の試作は背景の透過だけで成立するかを見る。** 飛行方向へ流れる細い波や誘導線を添える案は、その後の比較候補。音の軌跡は意味のある表示なので、切り替え専用の装飾を軌跡に混ぜない。画面全体の強い光、視点の回転、移動を伴う演出は入れない。

### 小さな地図 ↔ 実寸の地点

- 「小さな地図」「実寸」は、選択した地点の番号・色・名前でつなぐ。選択対象が保たれていることを見せる。
- 小さな地図を0.15〜0.25秒で薄くし、実寸の地点を表示する案。現実の校正座標をアニメーションで縮めたり伸ばしたりしない。
- 音の距離、耳の位置、飛行速度、共有時計へ地図の表示倍率を掛けない。
- 図の上を飛ぶ案内用ミニチュア機は別の設計事項。通常の旅客機を縮めて同じエンジン音を鳴らす仕様にはしない。

## 4. 音と日本語の作法

- 主役は旅客機の厚い響きと、飛行後に届く音。切り替え中も同じ発音・到来の流れを保つ。
- 操作音を入れるなら、短く柔らかい確認音を1回だけ（90〜150msを候補）。機体の方向を誤認させる移動音や大きな風切り音にはしない。操作音の有無を選べるようにする。
- 「音を休む」や消音中は操作音も鳴らさない。再入場・切り替えで勝手に音を再開しない。音声案内がある場合は操作音より言葉を優先する。
- 表示文は「現実に重ねる」「空に戻る」「小さな地図」「実寸の地点」など結果が分かる日本語を候補にする。短くしすぎて意味が曖昧になる箇所は、実機で読める大きさの補足を付ける。
- 画像内のマイクは将来の案。音声対話が接続されるまでは、押しても働かない機能を通常の操作として並べない。

## 5. 現行コードからどう近づけるか

画像制作時点の確認では、`apps/desktop/src/vr.ts`の`toggleEnvironment()`は見え方を切り替え、シーン側が背景・床などの表示を変更する構成。`SkyEnvironment.tsx`の空は不透明なシェーダーで描く。その後の操作部品の試作でも、背景をフェードする処理は追加していない。

後日の小さな実装候補は、端末内の「背景の見え方」を即時の二値切り替えから、目標値へ近づく表示係数へ分離すること。空・地面・木・霧・背景用の線へ反映し、機体・機体の照明・音源・時刻・校正から独立させる。空の透明化には、シェーダー出力と合成・描画順の確認が必要。ARで隠す軌跡も別に扱い、背景フェードへ無条件にまとめない。

- 対応端末では、現在の`immersive-ar`内で仮想背景を表示／非表示にする流れを利用できる見込み。
- 実際に`immersive-vr`セッションを終了して`immersive-ar`へ入り直す経路では、ブラウザの操作・許可をまたぐ。どの端末・入口でも継ぎ目なく切り替わるとは約束しない。
- 連打は最後の指定へ収束させ、切り替えアニメーションを順番待ちにしない。
- 動きを減らす設定では即時切り替え、または最短の透過にする。現実をすぐ見たい操作は演出完了を待たせない。
- 追跡・基準点が失われた場合の既存の非表示と再校正を優先し、演出中でも復帰案内へ移る。
- 1フレームごとに音源・形状・マテリアルを作り直さない。Quest 2を含め、透過描画の重なりによる負荷を測る。

## 6. 着手するときの確認順

1. 現在の位置合わせと会場の基礎を確認する。今回の構想追加で実機受入の完了数は増やさない。
2. 仮想背景だけを透過させる短い試作を作り、Quest 3とQuest 2で比較する。
3. 機体が急にずれない・薄れない、頭の動きに追従する、音が途切れない、片方の切り替えが他方を変えないことを確認する。
4. 連打、音の休憩、追跡喪失、AR非対応・入場拒否の復帰を確かめる。滑らかさと負荷を実機で記録する。
5. 入口と地図へ同じ動き・色・操作音を展開する。追加演出は原点の「見上げて聴く」を助けるかで採否を決める。
