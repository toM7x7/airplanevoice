# 手で触れ、声で頼める空 — 操作と動きの設計

2026-09-18 更新 / **共有ルームへ接続。Quest実機の指操作・装着交代は確認待ち。**

共有メニューは明るいカードと常設の小さなバーへ更新。指・ピンチ入力を共有アクションへ接続し、権限判定は既存処理を通す。「手元へ呼ぶ」で操作盤を現在位置の前へ置き直せる。下記のローカル試作に関する記述は初期設計の履歴。

**2026-09-18追記：** この文書の「声は未接続」はXR内の入力・表示を指す。PC通常画面にはAIの音声操作を別途接続済み。[最新の体験仕様](ai-guide-spec.md)に、指で選んで声で頼む、手操作中の値をAIが奪わない、古い音声依頼を上書きしない、盤が視野外のときの案内を整理した。いずれも今回の追加分は設計のみで、XR内のAIはまだ実機確認の対象にできない。

## 操作の前提を更新

来場者の基本は**手・指**。将来、声でも同じ操作を頼めるようにする。コントローラーは作り手の細かな編集と代替操作に使う。何もしないで旅客機と音を楽しむことも、一つの完成した使い方にする。

| やりたいこと | 来場者の操作 | 今回の状態 |
| --- | --- | --- |
| 操作を出す・しまう | 小さなバーを指してピンチ、または指先で触る | ローカル試作 |
| 遠くを選ぶ | 指して、親指と人差し指を軽くつまむ | 標準select入力を利用、模擬確認 |
| 手元のボタンを押す | 指先を前から近づけて触り、一度手前に戻す | 指先位置で判定、模擬確認 |
| 状況を知る | 日本語・アイコン・選択先の小さな反応 | 接点の輪と手向け案内を追加 |
| 操作盤を呼び戻す | 手だけで呼べる明示的な動作 | 共有版はバーの「手元へ呼ぶ」。バーが視野外なら元の場所を見る。グリップも継続 |
| 声で頼む | 「音を少し小さく」「現実に重ねて」 | **設計のみ**。マイク・認識・読み上げ・LLMは未接続 |

飛行機を指さすだけで操作盤が出ると誤作動になるため、最初は**バーを選ぶ意図があるときに開く**。手首のボタン、片手を返して短く静止する方式などは次の実機比較候補。顔の前の掌向き長押しピンチはQuestのシステム操作と競合するため割り当てない。[Metaの手入力仕様](https://developers.meta.com/horizon/documentation/web/webxr-hands/)

## 操作の動き — 2026-09-18の試遊で方向を更新

3案の比較後、ユーザーは「画面がやかましい」「シームレスに素早く操作したい」と評価。通常の操作盤は開く180ms／閉じる120msの短いフェードと、最大8pxの小さな移動へ変更した。PCはCSS、XRは軽いCanvas描画。機影、波紋、回転、項目の順次表示、演出選択パネルを外す。

SAOのような空間に浮くコマンドの印象を参考に、バーから必要な操作だけを出す。文字、アイコン、配色、余白、押した反応を整える。「飛行機らしさ」をメニューの大きな動きへ直訳しない。手入力・閉じた項目の無効化・動きを減らす設定・飛行時計を維持する。

[操作部品の現行仕様](control-components.md)。[第2稿](motion-v2.md)と6動画は未採用案の履歴として保存し、現行UIの動画と扱わない。
## 手入力の今回の実装

- 共有ルームと`controlSurface`の試作でWebXRへ`hand-tracking`を任意要求。未対応ならコントローラー操作を残す。
- 手入力では操作面を前方約62cm、幅約72cm・高さ約36cmに配置。頭について動かず、空間に残る。**初期試作値**なので文字と腕の負担を実機で調整する。
- ピンチ選択はブラウザの標準照準線を利用。直接タッチは`index-finger-tip`の最新関節姿勢をrig→板の座標→操作領域に変換。[WebXR Hand Input](https://www.w3.org/TR/webxr-hand-input-1/)
- 手前3.5cmより離れたところから同じボタンへ近づき、約9mm以内で一度押す。背面、横滑り、追跡再開直後では押さない。再押下には引き戻しが必要。数値は実機調整前。
- 近接ピンチとタッチの二重実行、閉じた項目・無効項目の押下を防ぐ。追跡喪失時は過去の座標を使わない。
- 簡易の関節マーカーと接点の輪を描き、近接中の照準線を隠す。自然な手のメッシュ、指の遮蔽、押し込みの表現は後続。
- 単体の旧UIは従来入力を維持。共有ルームは同じ指操作から既存の部屋操作へ接続。ローカル試作自体は共有命令を送らない。

## 声・AIのつなぎ方

「話しかける」を本人が押す入口を候補とする。待機／聞き取り／確認／実行中／結果を文字とアイコンで示し、マイクを使えないときはボタンで操作できるようにする。

`手・PC・コントローラー／将来の声 → 意図と操作ID → 実行可否・権限 → 既存エンジン → 結果表示`

認識した言葉と対象を短く示し、聞き間違いはやり直せるようにする。自分の音量と、部屋全体の飛行・会場編集を区別し、共有変更はサーバーでも検証する。案内AIも同じ操作IDと現在の状態を読み、存在しない操作を案内しない。音声やLLMの応答待ちで飛行を止めない。

まず少数の明確な命令で試し、その後に管制官の状況案内・MCP会場案内・Aivis Cloud等の読み上げを組み合わせる。音声APIの常時接続と費用発生は今回開始していない。

## 次の確認順

1. **今回：** PCで3案の動き・日本語・画面案の好みを選ぶ。試作の自動検証。
2. **Quest 3単体：** 素手で開く→選ぶ→閉じる→AR往復。距離・文字・疲れを調整。手だけでの操作盤の呼び戻し方法を決める。
3. **Quest 3＋2：** 既存の机A/B/Cの位置合わせと別視点を確認。T1〜T4の実機受入は0/4のまま。充電後の検証で更新する。
4. **共有版への適用：** 観覧／編集権限と復帰経路を保って新しい部品を組み込む。
5. **品質を並行改善：** コードで機体の輪郭・翼・エンジン・反射と軽量化を磨く。必要な部品はBlenderを検討。音・軌跡を含めた「見惚れる」を評価する。
6. **音声・AI：** 共通命令へ小さく接続し、遅延と費用を測る。

確認：`npm test`、`npm run build`、`npm run test:controls`、`npm run test:hands`。映像更新：`npm run render:motion`（新しい比較はRemotionを使用）。手のタッチ精度・快適さは模擬試験で完了判定しない。
