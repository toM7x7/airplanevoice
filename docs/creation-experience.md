# 一機をつくって、同じ空へ送り出す

2026-09-22。ローカル実装の整理。公開は認証切替後の追加指示まで保留。

## 体験の軸

一機を見上げて、音のする方へ顔を向け、見惚れる。その一機を自分で作れる入口を整える。会場案内・実フライトの再現は後段。同じ人がPCとQuestを同時に操作する想定は置かない。PC運営者とQuest来場者の別々の操作には、共有状態の版・権限・反映確認を残す。

| 場所 | 主な役割 | 操作 |
| --- | --- | --- |
| PC | 制作と展示運営 | 名前入力、寸法と音の数値編集、保存、部屋へ渡す、運営の航路・飛行設定。マイク不要 |
| VR | 初めての一機づくりと観察 | 形→音→名前→送り出す。少数の候補、2秒試聴、変更を戻す、手元の模型、保存済み作品の呼び出し |
| AR | 同じ機体を現実の中で眺める | 制作と選択を引き継ぐ。空・地面・格納庫・滑走路を隠す。制作模型と実寸の飛行を分ける |

自動チュートリアルの開始や有料会話の自動接続はしない。「一機をつくる」から入る。AIなしでも最後まで進める。

## データを三つに分ける

1. **自分の下書き**：このブラウザの制作作業。保存前の変更も再読込で復元し、作業画面は閉じた状態で再開する。
2. **保存した機体**：名前・形・音・航路を一つの作品として保管。ブラウザ保存と開催中の部屋の作品を一覧で区別。
3. **飛行中の機体**：送り出した時点の作品を固定。後から下書きを編集しても飛行中の機体は変化しない。

同名はあり得るため、内部ではIDで扱う。来場者が部屋へ提出した作品はサーバー発行の操作IDを使い、他人の作品のIDを渡しても上書きできない。同じ名前・同じ内容の再提出は既存作品を再利用する。ユーザーアカウントや恒久的な所有権の証明はまだない。

## 共通の制作操作とAI

`packages/core/src/creation.ts` に制作の操作語彙、`creation-workspace.ts` に下書き・戻す・ブラウザ保存をまとめる。PCのボタン、VRの指・コントローラー、AIツールが同じ操作を使う。独自のMCP通信は増やさない。

- GPT-Liveの案内：制作の該当手順を開き、対象ボタンを強調する。
- GPT-Liveの操作：候補の形・音・名前を下書きへ反映、手順移動、変更を戻す、試聴。
- 保存・共有・飛行：最終決定のボタンを本人が押す。AIのapplyでは実行せずguideへ誘導する。明示的な発話による最終確定は後続の設計対象。
- TypeSafe/Jev：既存の状況観察を維持。制作の候補選択や豊富な視野情報の判断は今回完成とはしない。
- 会話部品はXR入場でも維持し、VR内の「AIと話す」で開始・終了・ミュートを扱う。接続の準備・アクセスキー設定は先にブラウザで行う。

操作結果は実際の画面状態で確認する。部屋への提出はサーバーの反映通知を待って表示し、送信ボタンを押しただけで完了としない。

## 空間と縮尺

軽量なコード生成で滑走路（長さ3,000 m、幅60 m）、格納庫（屋根116×84 m、高さ約38 m）、駐機場を配置。仮想の観察場所から見える暫定配置であり、実空港や展示会場の測量値ではない。

制作中は実寸パラメータを0.009倍した手元模型を別オブジェクトとして表示。飛行する機体と音源の座標にはこの縮尺を使わない。模型は開いた位置に留まり、頭を動かしても顔へ追従しない。閉じて開くと呼び直せる。

**格納庫からの地上走行・離陸・途中帰還・着陸は未実装。** 現在の「飛ばす」は共通の時刻から始まる周回飛行。格納庫が見えることを離発着の実装完了とは扱わない。

## Cloudflareの機体管理

今回は既存のSkyRoom Durable Object / SQLiteの部屋データに作品を保存する。新しい契約・データベース・ストレージ・認証方式は追加しない。保存後に配信する既存の順序を維持する。

| 保存先 | 寿命・上限 | 意味 |
| --- | --- | --- |
| ブラウザの下書き | 1つ、ブラウザデータ削除まで | 続きから制作 |
| ブラウザの格納庫 | 24機、ブラウザデータ削除まで | この端末での保存。別端末には自動移行しない |
| 部屋の格納庫 | 24機、通常1時間／展示8時間 | PC→Quest受け渡し、開催中の作品共有 |
| 飛行 | 実行中の一便＋予約一便、一便最大3機 | 各便の形・音・航路を固定して共有 |

来場者には自分の作品の追加と送り出しを許可。部屋の航路変更、他作品の削除、自動運転の切替は運営に残す。切断中・反映待ち・次便予約済みは飛行ボタンで分かるようにする。

恒久的なクラウド格納庫は次の別工程：管理者の認証、作者と閲覧者の権限、作品の版・削除・バックアップ、容量上限を先に決める。共有リンクだけで恒久的な所有権を判断しない。メタデータはD1等、将来の外部モデル・音素材はR2等を検討できるが、現時点で採用・配置していない。
