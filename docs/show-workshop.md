# 空の演目づくり・フライバイ観測所

更新: 2026-09-15 / v0.7.0

2026-09-16追記: 本書は公開済み機能の操作資料。ユーザーから作成の複雑さと企画の方向のずれを指摘され、旅客機を見上げる体験を中心に[方針を再整理](project-direction.md)している。演目作成を今後の中心とする決定ではない。今回アプリの操作は変更していない。

## 今回できること

「演目をつくる →」から、1〜3機それぞれに機体・2地点航路・速度・開始時刻を設定する。3つの出発点を用意した。

- **交互に見上げる**：2機が別の航路を時間差で飛ぶ。
- **双発と四発を聴き比べる**：同じ航路へ、双発と四発を30秒差で飛ばす。音の重なりも残るため、完全に独立したA/B再生とは異なる。
- **三つの高さ**：低い双発、中高度の四発、高い大きな四発を組む。

機体は「ゆったり四発」「長い翼の双発」「大きな四発」、航路は「正面のフライバイ」「斜めの往復」「低く、ゆっくり」「高い大回り」から始められる。実在する機種を再現したプリセットではない。

## PCで作って試す

1. 演目のパターンを押す。各機の予定をまとめて反映する。
2. ST-01／02／03を選んで編集する。先頭機の開始は0秒、追加機は0〜180秒後に設定する。
3. 「機体・航路を細かく調整」で寸法・エンジン数・2地点・高度・幅・ゆらぎ・シード・速度・傾きの追従を変更する。
4. フライバイ観測所で、各機の最接近と、その地点で出た音が届く予測時刻を見る。
5. 「この演目で飛ばす」。飛行中の「届いた音を見る」で、その観察者へ実際に届いた音の発音位置を地図に重ねる。
6. ひと休みで全体を停止。編集へ戻ると演目を保つ。終演後は同じ予定・同じ音の設定で再試演できる。

演目は一回ずつ試演する。周回ごとに航路を変える自動継続は、通常の航路モードで引き続き使える。演目の飛行中は設定を変えない。

## 保存・受け渡し

有効な変更は端末へ保存する。JSONの書き出しと読み込みに対応し、単体航路へ戻っても最後の演目の下書きから再開できる。リセットはこの下書きも削除する。保存が使えない環境でもその画面では試演できる。

「この空をQuestへ渡す」は、各機の機体・航路・開始時刻を含む演目全体を渡す。受信後もEDITで停止し、VR入場・開始は端末ごとに操作する。複数Questのオンライン同期はまだ行わない。

単体の共有形式は従来のversion 1を維持し、演目はversion 2を使う。旧URLは新アプリでも読める。演目URLを扱うにはv0.7.0以降が必要。QRは従来どおりURL全体1,800文字以内で、それを超える場合はURLを使う。

## 観測表示の読み方

- 細い航路は予定。機体アイコンは現在位置。耳の点は観察者の位置。
- 「届いた音」の点は、その位置で出た音が現在の観察者へ届いた履歴。点は既存の航跡保持時間に従って消える。
- 時間図の棒は開始から飛行終了まで、●は最接近、○はそこで出た音の到来予測。
- 予測は512点の中の最短距離から求めた目安。観察地点と遅延倍率に応じて更新する。音量のピーク時刻、実測音圧、会場の反射音を示すものではない。

## エンジンの境界

`ShowRecipe`はタイトルと最大3件の`WorkshopRecipe + startSec`を持つ。全件を検証・コンパイルした後、一括反映する。成立しない2地点や速度などがある場合、直前の有効な演目を保つ。

各機の航路長・速度から終了時刻を求め、最後の機体と全音声到来キューの終了を待つ。描画・機体情報・選択範囲・音の生成は各機の設定を見る。通常モードの位置ずらし航路は維持する。衝突回避や離発着を解く機能はまだ含まない。

音は端末内で作る合成音。四発と双発のファン成分とゆっくりした揺らぎを変え、素材のRMSを同じにする。見た目から実機の音響特性を推定する仕組みではない。実録音・機種固有のモデル・AI生成音声は未導入。

## 再試遊の焦点

1. 旅客機らしい厚みが増え、鋭さや聞き疲れが減ったか。Quest本体スピーカーで確認する。
2. 各機を選ぶ→変更する→同じ空で飛ばす流れが分かるか。
3. 最接近と音の到来を見比べることが、空を探す楽しさにつながるか。
4. 2機の時間差を変えると、見上げる順番や静かな余白の違いが分かるか。

今回の実装・自動検証と、人による聴感・操作感の受入は[進捗](progress-overview.md)で分けて記録する。
