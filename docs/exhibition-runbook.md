# 展示当日の短い運用手順

## 持ち物と入口

- ノートPC、Quest 3、充電、ネット回線、必要ならUSBケーブル。
- https://airplanevoice.pages.dev/?shared=1 をPC・Questにブックマークする。
- リリースの60秒／30秒動画とA4横2枚をノートPCに保存。ネット不調時は動画を再生できるよう確認する。
- Quest 2は今回の主運用に数えない。位置合わせ前の会場案内やスマホARは展示の完成機能として案内しない。

## 開場前

1. 古い開発タブや別端末の不要な接続を閉じる。共有は現状4接続まで。最大24機と接続枠は別。
2. PCで格納庫・共有状態を確認。既存の機体を保存・読み込みできるか確認する。
3. 「部屋・運営」で当日の機数、自動便の対象、Jevのオンオフを確認する。最大値から始めず、Questで余裕のある機数を選ぶ。
4. QuestでVRに入り、メニュー・模型・レーダーが届く位置にあるか、掴んで動かせるか確認。
5. 一機の出発、飛行、音、選択と解除、AR/VR切替、終了を試す。
6. 音声対話を使う場合だけ開始。終えたら会話終了とマイク停止を確認する。

## 来場者の動線

「一機を選ぶ／簡単に作る」→「名前を付ける」→「本人が飛ばす」→「見上げて音を聴く」→「気になる機体を選ぶ」→「全体へ戻す」。PCは詳細編集と運営補助を担当する。

空きがあれば約15秒後に出発するが、混雑や滑走路予約で待つことがある。AIの提案は下書きであり、保存・共有・出発は最後に本人が確定する。

## 困ったとき

| 症状 | まず行うこと |
|---|---|
| 共有への再接続待ち | ネットと不要なタブを確認。4接続満員の可能性。公開データを消して直そうとしない |
| 音が出ない | 初回の音ボタン、端末音量、選択機だけのモード、GPT発話中の減音を確認 |
| AIが使えない | 手操作を使う。何度も連打して課金リクエストを重ねない。PCの公開AI接続を確認 |
| 案が希望と違う | 未共有の下書きなら戻す／手動調整。建築様式や任意3D生成は現在の景色機能の範囲外 |
| VRの盤が遠い | 手元へ呼ぶ操作と取っ手で調整。必要ならブラウザへ戻り再入場 |
| 動作が重い | PCの運営で同時機数や自動便を減らし、景色の密度を下げる |
| 当日直せない | 安定版に戻すか、保存しておいた動画を案内に使う |

## 会期中の開発

修正前のコミットを記録→一件だけ修正→関連テストと手動確認→GitHubへpush→必要時に公開。展示中にデータ形式や部屋の識別子、所有権の大改修をしない。公開内容を切り替えたらPC・Questで意図して再読み込みする。

## 終了

会話を終え、Jevと自動便の運営方針を確認し、不要なら停止する。公開AIの自動課金上限は設定されていないため、会期後の公開継続は別途判断する。格納庫をファイルへバックアップしてから端末を閉じる。
