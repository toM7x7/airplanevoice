# ARの2モード

更新: 2026-09-16 / **設計に追加。AR・会場測量・管理権限・MCP接続は未実装。**

## 1. 現実の空間で機体を観察する

ユーザーが希望する基本AR。現実の周囲を透過表示し、仮想の地面・建物・山・林・空背景を隠して、旅客機をしっかり見られるようにする。機体の飛行と各観察者に届く立体音響は維持する。

- モード選択はVRと区別し、対応端末で`immersive-ar`を利用する設計。仮想背景を透明にするだけでAR対応済みとは扱わない。
- 軌跡・波紋・操作盤は機体とは別に表示を選べるようにする候補。「機体だけ」を選んだら補助表示も隠す。
- まず現在の仮想空域を自分の前に置く。現実の会場や他端末との座標一致は第2モードの校正と分ける。
- Quest 3で現実の周囲の見え方、機体の視認性、音、終了・休憩の操作を実機検証する。

## 2. 展示会のブースへ案内する

ユーザーの発案を、後続の発展候補として記録。事前の展示会マップと当日の実測から位置を合わせ、対話や展示会MCPを使って行き先を相談すると、機体がそのブースの方向へ飛んで案内する。

### 管理側で設定すること

- 会場図の版・縮尺・単位、基準点ID、当日測った対応座標、各点の測定精度。
- ブースIDと会場図上の位置・入口・案内用到着点。古い配置や仮の座標を区別する。
- 会場図から体験空間への変換（原点、向き、縮尺）、検証点のずれ、校正版、適用した時刻。
- 校正の保存・プレビュー・適用・前の版へ戻す操作。管理用コマンドは候補であり、現時点で存在するコマンドとして案内しない。

複数の離れた基準点で変換を推定し、計算に使わなかった検証点でもずれを確認する。必要点数・許容誤差・高さの扱いは、会場図と測量方法から決める。各Questのローカル座標から同じ会場座標へ合わせる手順も必要。部屋URL／QRで入室しても、現実の位置・向きは自動一致しない。

### 権限と案内の流れ

1. 管理者が測量値・配置・校正を設定し、現地で確認して有効化する。
2. 参加者が行き先を対話で相談。MCPは展示の情報取得に使い、紹介文を操作命令として実行しない。
3. LLMの提案先を既知のブースIDへ解決し、エンジンが案内用の航路を検証する。
4. 参加者が行き先を確定したら、共通の便として飛ばす。生成待ちでも既存の飛行や手動操作は続ける。
5. 現地の通路・人の動線を踏まえて案内する。旅客機の飛行線と人が歩いてよい経路は別に設定する。

管理権限はサーバー側で判定する。画面を隠す・URLに`admin`を付けるだけでは認可にしない。現在の部屋への編集招待は機体・航路の試作操作用であり、会場校正の管理権限を与える仕組みではない。ログイン方式や管理用資格情報の持たせ方は、実装前に選定する。

MCPの情報だけで実空間の座標・通路・安全性が保証されるわけではない。配置更新や追跡のずれ、通信断では校正状態を示し、案内を止める／手動選択へ戻せる構成を検討する。

## 実装順の位置づけ

現在の優先はPC＋Questの共同編集・飛行。その次の独立した検証として基本ARを扱い、展示会モードは会場データ・管理権限・測量／端末間校正・MCP案内の段階に分ける。今回のメモで展示会連携の提供時期や実装完了を確約しない。
