# 条件から変わり続ける飛行

更新: 2026-09-15 / v0.4.0 公開・動作確認済み

## 確認した方向

ユーザーは「周回ごとに航路が少しずつ変わり、自動で飛び続ける」を選択。展示会で同じ人が差分を見比べ続けることは前提にせず、その場で見る飛行が条件に応じて変化する体験を育てる。まずPC中心で開発し、スマホの実機試遊は後で行う。

天候設定、機体同士の関係、シミュレーション条件による変化も発展先として受領。以下の現行モデルと将来候補を区別する。

## 今回の操作

1. 航路を描くか、つくる実験室で2地点の航路を用意する。
2. 「周回ごとに変化して飛び続ける」をONにし、変化の幅を調整して飛ばす。
3. 初周はそのまま。全機の飛行と音到来が終わると6秒休み、次の航路を生成する。通常の開始前の余白2.5秒を経て飛行する。
4. 気に入った周回は「この航路を残して編集」で保存する。通常の「航路を描き直す」では最初の航路へ戻る。
5. 自動継続をOFFにすると、現在の飛行を最後まで眺められる。一時停止は飛行中と周回間の待ち時間の両方に効く。

新しいブラウザ起動時は自動継続OFF。明示的に残した航路だけを既存の端末保存へ書き込む。自動変化中の航路で、保存した設定を毎周上書きしない。

## 現行の生成条件

| 条件 | 反映 |
| --- | --- |
| 最初の航路・2地点・シード | 変化の基準。同じ入力と周回番号から同じ航路を再現 |
| 周回番号 | ゆっくり変わる周期関数の位相。毎フレーム乱数を加えない |
| 変化の幅 | 基準からの変化量。画面では10〜100% |
| 描線・プリセット | 中心を保った小さな回転・拡縮・周期的な起伏 |
| 2地点航路 | A/Bの位置と指定通過高度を保ち、回り込みの幅・起伏量を変える |
| 飛行速度・傾きの追従 | 現在の設定を保持。検証済みコンパイラーへ渡す |
| 機数・開始間隔 | 全機の飛行と音到来が終わる時刻を決める。現時点では航路形状を相互調整しない |

各周回は最初の航路から生成する。前周に変形を重ね続けないため、長時間運転でも変形が累積しない。描線の回転は最大約12.6°、拡縮は最大±12%、高さの変化は最大35mに変化の幅を掛けた範囲。隣接周回ではゆっくり変化する。2地点の幅は最大±20%を値域400〜1500mに収め、起伏量は既存の0〜1に収める。

旋回・勾配・高度・空域を既存のコンパイラーで確認し、成立しない場合や別の旋回への置き換えが必要な場合は、自動継続を止める。直前の有効な航路を保持し、理由を表示する。これは観察用の生成モデルであり、機体性能を解く物理シミュレーションではない。

## 時刻と音の扱い

- 航路更新は全機の音到来が終わった周回間に限定。飛行途中の座標や発音位置を飛び移らせない。
- 新しい航路ごとに全機の予定と音到来キューを作り直す。各機の開始間隔、音の注目、選択している機体IDは保持。
- タブを離れた場合は周回間も一時停止。戻っただけでは再開せず、再開操作を待つ。
- 継続はローカルのシミュレーション時刻を使う。ブラウザのフレーム単位で遷移を処理する。複数端末の共通開始時刻・厳密な同期は後の段階。
- 航路の一時的な履歴を無制限に蓄積しない。ログ・航跡・音声枠は既存の上限内に保つ。

## これから加える条件（未実装）

| 候補 | 先に決めること |
| --- | --- |
| 天候・風 | 空の見た目だけを変えるのか、機体の移動や音の到来にも作用させるのか。条件と結果の因果関係をそろえる |
| 機体ごとの性能 | 寸法、質量、推力、旋回条件のうち何をモデル化し、何を演出値にするか |
| 他機との関係 | 開始順、空域の割り当て、近接、衝突回避の必要範囲。現在の位置ずらしを管制と呼ばない |
| 展示の条件 | 会場の空間、滞在時間、通過頻度、音量、無操作時の見せ方 |
| 観察するAI | 共通の条件と飛行記録を読み、飛び方・響き・構図の観点から気づきと次の案を返す |

条件を追加するときは「入力条件→生成→飛行条件の検証→予定の確定→観察」の順に接続する。AIの提案は条件の入力候補であり、毎フレームの位置計算には使わない。天候、反射・残響、機体間の相互作用、AI接続は今回の実装には含まれない。
