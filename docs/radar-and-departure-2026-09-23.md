# VRレーダー・音響マップ・参加者の出発待ち（2026-09-23）

## 今回の範囲

原点は、旅客機を見上げて、遅れて膨らんで届く音を楽しむこと。会場マップとMCP案内は次の仕様相談として残し、仮想の空の運行とVR操作を整える。

### 参加者の操作

1. VRの空メニューから「新しい機体をつくる」「機体を編集」「保存した機体」を選ぶ。
2. 手元の模型はメニューの少し上へ現れる。空の共有便は飛び続ける。
3. 「形・寸法・尾翼の色・音・名前・AI相談」で編集する。寸法は胴体50〜85m、翼幅45〜85m、2mずつ調整。変更は下書きに反映。
4. 「この機体を飛ばす」で出発待ちに入る。空きがあれば約15秒後、先客がいれば順番に出発。最低15秒間隔、音の余韻を含む枠が空くまで待つ。待機上限64便。
5. 「フライトレーダー」で別の板が正面上側に開く。手元のメニューは畳まれ、レーダーを閉じると戻る。

### 2つのレーダー表示

- **機体・航路**：上から見た航路、飛行中の機体、現在地、選択機体の名前・高度・距離。位置が重なった機体は繰り返し選ぶと切り替わる。
- **音響マップ**：計算上、到来した音の発生位置と現在の機体位置のずれ。金色の点・輪と点線で示す。実測音圧や会場反射音のヒートマップではない。
- PCとXRで同じデータを使用。レーダーの選択は通常の機体情報・AIの選択コンテキストにも反映。
- 描画は概ね毎秒5回に制限。音の履歴は最大480点、通常の3D音の軌跡は引き続き最大384点。

### PC「部屋・運営」

- 同時飛行上限：3 / 6（標準）/ 9 / 12 / 18 / 24機。24機は実機負荷を確認して使用。
- 保存機体ごとに自動便の対象を選択。「すべて使う」「自動便だけ止める」。対象変更・停止で取り消すのはまだ飛んでいない自動便。参加者の予約と飛行中の機体は維持する。
- 参加者の出発待ちに名前と残り秒数を表示。「次の便を取り消す」は先頭の1便のみ。
- 運行方針：空きに合わせる / 次々に飛ばす / ゆったり眺める。Jevオフでも動く。
- 160文字までの運用コメントを保存し、Jevがオンのとき次の自動便の判断へ渡す。選択可能な出発間隔と高度候補の範囲に限定。保存機体や飛行中の航路の書き換えは行わない。
- 機数上限を下げても受付済みの参加者予約は保つ。既存便が終わるにつれて新しい上限へ移る。

### 掴み操作

- 左右の取っ手の接触範囲を拡大。指でつまむ、手を開いてから握る、コントローラーのトリガー・グリップに対応。
- 指を閉じる途中で取っ手から近くの模型へ対象が切り替わる原因を再現。最初に触れた取っ手を短時間保持して修正。
- ボタン面は取っ手判定から除外。追跡再取得・最初から閉じた手・普通の頭の移動では掴まない。
- メニューの位置はユーザーが決める。飛行開始による移動はしない。編集開始時は模型だけを呼び戻す。

### GPTライブとの連携

- 現在のPC/VR/AR、パネル名、押せるボタン名、選択機体をコンテキスト先頭に配置。従来の320文字切り詰めでVR情報が落ちる問題を解消。
- 選択や編集の切り替えは約0.5秒単位で検出し同期。通常の状況更新は5秒間隔。
- 飛行スロット番号とユーザー名・保存機体IDを分離。スロットを別の便に再利用したら古い選択を解除する。
- VR中は「保存した機体」「機体を編集」など、その場の日本語の操作名を使う。新規作成は確認画面を開き、寸法変更は共通コマンドで下書きへ反映する。
- 保存・出発は引き続き本人が確定する。
