# 本番環境の相談 — 配信・共有・保存・利用状況

更新: 2026-09-16 / **共有試作はCloudflare Freeを採用。長期運用・DB・AI・課金契約は引き続き検討。**

## 今回の位置づけ

2026-09-16追記: ユーザー指定アカウントのWorkers Freeを確認し、PC＋Questが双方から操作する共有試作をCloudflareへ配置した。Workers＋SQLite型Durable Objectsで1時間の部屋を保存する。D1・R2・AIサービスや有料契約は追加していない。[構成と上限](shared-sky.md)。以下は長期運用まで含む比較として残す。

ユーザーから、本番環境はGitHub Pages、Cloudflare、Vercelなどを、裏側の仕組み・利用データの保存費用・長期的な効果まで含めて相談したい、という意向を受領した。

GitHub Pagesはv0.3の**試遊版の配信先**。そこで公開したことを、本番基盤の選定完了とは扱わない。実装を試し、必要な機能と利用量を見てから判断する。本書は思いつきの保管より具体的な検討資料だが、実装への着手指示ではない。

## まず分ける仕組み

| 役割 | 必要になるもの | 設計で決めること |
| --- | --- | --- |
| 体験の配信 | アプリ、3D部品、音素材 | 初回読み込み時間、配信量、更新、オフライン保存 |
| 共有ルーム | 参加者、飛行予定、開始時刻、予定の版 | 同時接続、途中参加、再接続、同室と遠隔 |
| 作品の保存 | 機体・航路・演目のレシピ | 自分の作品、共有、改訂履歴、削除、書き出し |
| 利用状況 | 開始、完走、再周回、編集、保存など | 何を改善したいか、記録の粒度、保持期間 |
| AI | 管制案、説明、対話キャラ | 回数、会話の長さ、音声の有無、待ち時間と利用上限 |
| 運営 | 不具合記録、バックアップ、費用確認 | 展示当日の復旧、日常の保守、作業負担 |

共有中の状態、長く残す作品、利用分析を同じデータとして保存し続けない。用途ごとに必要な頻度と寿命を決める。

## 候補の一次比較

2026-09-15に公式資料を確認した。以下は機能を踏まえた設計候補で、実機比較の結果ではない。

| 候補 | このアプリで考えられる構成 | 判断に使う点 |
| --- | --- | --- |
| GitHub Pages | 単体の体験配信。共有・DB・AIは別のサービス | 今の試遊に使える。本番のバックエンドは別途必要。商用SaaS向けの提供制限もある |
| Cloudflare | Workersで配信/API、Durable Objectsでルーム、D1で作品・集計、必要ならファイルストレージ | 部屋単位の予定管理と組み合わせやすい候補。休止できる接続設計、DBの読み書き量、復帰を実測する |
| Vercel | アプリ/API、WebSocket対応Functions、外部データストアでルームと作品を共有 | 管理画面やWeb機能も含めて比較。WebSocketは現在ベータ。関数の終了に伴う再接続と共有状態の復元を試す |

参照: [GitHub Pagesの利用範囲](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)、[Cloudflare Workers](https://developers.cloudflare.com/workers/platform/pricing/)、[Durable Objects](https://developers.cloudflare.com/durable-objects/platform/pricing/)、[D1](https://developers.cloudflare.com/d1/platform/pricing/)、[Vercel WebSockets](https://vercel.com/docs/functions/websockets)、[Vercel Storage](https://vercel.com/docs/storage)。

**現時点の見立て:** 同じ空を複数Questで共有することを中心にすると、Cloudflareを最初の比較候補に置く理由がある。Vercelも候補に残す。選定は2台の接続・途中参加・再接続を動かし、保存と費用を測ってから相談する。配信先を理由に、現行のThree.jsの飛行・音響エンジンを書き直す必要はない。

## 費用を何から見積もるか

概算は **基本料金 + 配信/API + 共有ルーム + DB + ファイル + AI + 運用** に分ける。最安の基本料金だけで総額は決まらない。

- Cloudflare Workersの有料プランはアカウントあたり月額最低5米ドル。基本枠を超えるリクエストやCPU使用量などを加える。これはアプリ全体の確定月額ではない。[公式料金](https://developers.cloudflare.com/workers/platform/pricing/)
- Durable Objectsはリクエストと稼働時間等で計算する。WebSocket Hibernationを使って休止できる時間を作ると、継続稼働の時間課金を減らせる。高頻度の処理が続くルームでは、休止を前提に見積もらない。[公式料金](https://developers.cloudflare.com/durable-objects/platform/pricing/)
- D1は読み取った行・書き込んだ行・保存量が基準。無料枠は日次の上限超過でクエリが止まるため、展示当日の集中も確認する。有料枠は含まれる量と超過分を分けて計算する。[公式料金](https://developers.cloudflare.com/d1/platform/pricing/)
- Vercel Proの基本料金は月額20米ドル、デプロイ可能な1席と20米ドルの利用クレジットを含む。超過利用、追加席、外部DB等を別途確認する。Cloudflareの5米ドルと同じサービス一式が含まれる比較ではない。[公式料金](https://vercel.com/docs/plans/pro-plan)
- AIはモデル、文字量、音声時間、1体験あたりの会話回数が未定なので、現時点では総額を置かない。

### 記録の粒度の例

**仮の比較:** 200体験で、1体験20件の節目を残すなら4,000イベント。1体験10分間を毎秒60回記録すると7,200,000イベントになる。これはイベント数の単純計算で、DBの請求額や実際の書き込み行数ではない。索引、集計、再送の設計でも読み書き量は変わる。

現在は端末内ログと手動書き出しだけ。サーバーへの利用データ収集は実装していない。

## 長く続けるために知りたいこと

候補を挙げ、採用時に目的と測り方を決める。

- 始めた人が、一周を見終えるか。
- もう一周するか、機体や航路を変えて試すか。
- どの操作や機能で止まるか。
- 気に入った作品を保存するか。
- 後日また使うか。再訪を測る場合は、利用者の識別方法と保存期間も決める。
- Questでフレーム時間や音の途切れが、体験継続に影響するか。

操作回数だけでは「楽しかった」「音の方向が分かった」は分からない。短い感想と組み合わせる。個々の視線や位置の全履歴は、具体的な検証目的が生じた時点で必要性を判断する。

## 本番を選ぶ前の相談項目

1. 展示会の同時端末数と、通常公開時の利用規模。
2. ゲストで体験する範囲と、作品を後日持ち帰る方法。
3. 作品・利用状況・不具合ログの保存内容と期間。
4. AIは文章案内か音声対話か、1体験あたりの使用量。
5. 展示当日と通常月に許容する予算、運営の手間。

ここで方向を合わせてから、1ルーム・2端末・作品保存・小さな利用集計で比較する。現段階では候補サービスへの移行、DB作成、AI契約を進めない。
