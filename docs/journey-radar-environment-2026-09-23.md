# 独立レーダー・帰還・機体／空間づくり

2026-09-23。原点は「地上から見惚れる旅客機と、遅れて届く音」。会場マップの前に、共有する空の制作と観察を整える。

## 今回の範囲

| 項目 | 実装したこと | 確認の限界 |
|---|---|---|
| レーダー | 観察時は初めから表示。PCは上端をドラッグ、VRは左右の取っ手をつかむ。メニューと独立し、離した後は固定 | 模擬Questで確認。実機での手の追跡・届きやすさは要試遊 |
| 多機運航 | 最大24機、参加者予約優先、自動便の対象機・一時停止をPC運営で指定 | 現在の公開設定を維持。24機のQuest実機フレームレートは未計測 |
| 帰還 | 新しい飛行は離陸→複数周の巡航→進入→着陸・減速→格納庫へ。離陸・着陸の滑走路使用時間を予約 | 描画用の経路。脚、操舵、空力の物理再現ではない。既存飛行は旧経路のまま終了 |
| 出発 | 空きがあれば約15秒後。参加者同士は最低15秒間隔。滑走路・機数が埋まっていれば待つ | 「必ず15秒で離陸」ではない。着陸が重なる場合は巡航を延長 |
| 飛行中の指示 | 選択機に「頭上を通る」「広く回る」「少し高く」。約5秒後から滑らかに寄り道し、約2分で戻る | 巡航のみ、1機4回まで、指示実行中は再指示不可。変更先の近接予測で拒否する場合あり |
| 聴き方 | 全体／選択機を強調／選択機だけ。同じ操作をGPT-Liveにも公開 | 選択機だけの音は各端末の設定。ほかの参加者の音を変えない |
| 機体 | 6形状、6色、胴体の太さ・後退角・エンジン寸法・翼端・胴体色。PCは詳細、VRは3候補ずつ切り替え | 手元模型の造形はコードによる近似 |
| Jevの制作相談 | PCのAI相談欄に「Jevで機体案を作る」。構造化された候補から下書きを一括編集 | 実APIの有料呼び出しは未検証。モデル結果の検証・編集途中の結果破棄は模擬応答で確認 |
| 空間づくり | PCの観察画面から公園・都市・住宅街・海辺・空港。密度・高さ・道路幅・緑・配置番号を変更 | 下書きプレビューはローカル。「みんなの空に反映」で共有。建物の反射・遮音は未実装 |
| PC自由視点 | WASD、Q/E、ドラッグ、Shift。「元の立ち位置へ戻る」 | PCだけの視点。他端末のQuestを移動させない |

### 運航判断の境界

- 裏方Jevは既存の構造化された混雑・音の重なり情報を使い、次の自動便の候補を選ぶ。飛行姿勢の毎フレーム制御はコードが行う。
- 飛行中の指示はサーバーで時刻・対象・範囲を再検証し、2秒刻みの近接予測を行う。これは近接を減らす検査であり、全経路・全瞬間の衝突回避保証ではない。
- 旧形式の複数機をまとめた演目が残っている間は、飛行中の航路変更を受け付けない。
- 変更前に放たれた音は元の発音位置を維持し、これから発する音だけを新しい経路に合わせる。
- 保存・共有・出発の最終決定は人が行う。Jevの機体案とGPTの空間案で勝手に公開・出発しない。
- ARでは仮想の地面・建物を隠す。今回の街並みはVRとPC向け。

## 試す順序

1. ページを更新し、QuestでVRへ入る。レーダーの左右の取っ手をつかみ、手を離して見上げる。メニューが一緒に動かないことを確認。
2. 「飛行中の機体」で名前を選択。「選んだ機体に指示」から頭上通過を試す。離陸直後や混雑時の拒否メッセージも確認。
3. 「音量・聴き方」→「聴く機体を選ぶ」で、全体と一機だけを比較。
4. PC「つくる」で形・寸法・色を調整。VRでは「別の3パターン」で追加の候補を見る。
5. PC「空を眺める」→「空間づくり」で都市を試し、「みんなの空に反映」。Questで建物の間から空を見る。
6. 出発から着陸・格納庫への帰還まで一便を観察。混雑時は巡航が延長される。
7. 必要な時だけAIを開始。ユーザーが付けた機体名で選択し、音・航路・機体下書きを相談する。

## スマホと同じ空間を覗く案（次の検証）

AndroidとiPhoneの両方を対象とする。同じ飛行時刻・機体・景色を配信する部分は既存の共有状態を再利用できる。机の同じ位置に重ねるには、スマホ独自のカメラ姿勢と、共有座標への変換が別途必要。

- Quest：運営者が固定机の基準点を合わせ、立ち位置を固定。
- スマホ：まず共有3D表示。実空間に重ねる試作では、机に寸法が分かる画像マーカーを置き、端末ごとの原点・向き・縮尺を合わせる。
- Android：ARCore対応機＋対応ブラウザならWebXRを検証する。[Googleの要件](https://developers.google.com/ar/develop/webxr/requirements)。
- iPhone：AndroidのWebXR方式と同じ動作を前提にせず、カメラ画像のマーカー追跡を別途検証する。Three.jsへ接続できる画像追跡の候補として[MindAR](https://hiukim.github.io/mind-ar-js-doc/)がある。採用・端末動作は未確定。
- 入室QRはURLを開く手段。読むだけで原点・姿勢・縮尺が揃うわけではない。ジャイロだけでは移動距離も求められない。
- Questのカメラ映像をスマホへ転送する方式とは別。各端末が同じ機体を、それぞれの実位置から描画する。

次の合格条件は、机の角から見た同じ機体位置、端末を動かした時の見え方、30秒・60秒後のずれ、マーカーを見失った時に無理に追い続けない表示。スマホの空間ARは今回の公開機能には含まない。
