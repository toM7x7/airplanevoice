# 開発と検証

## アーキテクチャ

- `packages/core/src/route.ts`: 入力検証、点間引き、RDP簡略化、周期B-spline、旋回・高度調整、弧長サンプリング、チェックサム。
- `flight.ts`: 経過時刻から位置・接線・バンクを算出。メートル単位、Yが上、Z負方向が初期の正面。
- `acoustics.ts`: 決定論的な発音イベントと観測者ごとの到来時刻。消費済みイベントを記録し、二重到来を防止。
- `airspace.ts`: 1〜3機の計画、比較用航路の配置、開始間隔、機体別の音到来キュー、注目／全体のゲイン計算。
- `tower.ts`: 型付き事実イベントから定型字幕を選ぶ。表示間隔、優先度、期限、近接時の抑制。
- `observation.ts / AircraftInfo.tsx`: 機体の状態を読み取り、速度・進行方位・高さ・距離を表示。選択と音の注目は別々に管理。
- `evolution.ts / EvolutionControls.tsx`: 基準航路・周回・変化量から次の案を生成。`Experience`で全機の音到来待ち、6秒の休み、自動再開・停止・保存を管理。`FlightMap`は現在の主航路とST-01を表示。
- `experience.ts`: EDIT → COMPILE（開始前の余白）→ FLY → ARRIVAL → INTERLAP。Pause、Undo、Reset、ログ。
- `recipe.ts`: 検証可能な演出値と、低音層を交互に変えるルール。
- `workshop.ts`: 機体・2地点航路・飛行設定の共通JSON、値域検証、固定シードによる周期曲線。
- `Workshop.tsx / Aircraft.tsx`: パラメーターとレシピ編集、寸法・配置の反映、窓の一括描画、遠距離の細部省略。
- `apps/desktop/src/Scene.tsx`: 3D空間、固定観測地点、機体、線、到来位置の輪。
- `audio.ts`: ユーザー操作でAudioContext開始。HRTFパン、フィルター、Doppler再生速度、音量包絡、コンプレッサー。

到来処理は飛行中にも進む。発音点の音と航跡は同じ到来計算から発生する。音の再生位置は発音した位置に固定する。可視の輪は発音位置での到来表示で、空間を伝わる球面波を厳密に描くものではない。

## 実装上の上限と近似

- 最大1,000入力点、512経路サンプル。発音間隔100ms。
- 可視航跡は128点×設定機数（最大384点）、輪8個、音声は1機6ノード群・全体18ノード群、ログ2,000件。
- 遅延倍率は1〜3倍。×1の基準音速は343m/s。
- 初期速度58m/s、レシピでは35〜75m/s、最大25度バンクの演出モデル。傾きの追従時間は0〜3秒。実機の失速速度や運航性能はモデル化していない。
- 静止観測地点を選び、カメラの向きは自由に変えられる。飛行中の地点切り替えは、瞬間移動による音の不連続を避けるため無効にしている。
- コアの到来キューは移動した観測者の位置でも再計算できるが、連続歩行の体験検証は未実施。
- 250ms以上遅れた音の再生は破棄して、タブ復帰時の一斉再生を避ける。非表示時はローカル体験を一時停止する。
- 音色は録音素材を使わない仮合成。機体は寸法とエンジン数を変更できる検証用メッシュ。形状と飛行性能・音色の自動連動はない。
- 端末保存は航路と機体。端末間共有、アカウント、サーバー保存はない。
- 追加機の航路は位置をずらした比較用。安全な空域割当や衝突回避は未実装。設定変更は編集時に行い、聴き方と字幕ON/OFFは飛行中にも変更できる。
- 機体別ゲインを時定数0.25秒で変更。音声出力時刻とシミュレーション時刻は別で、時間送りテストでは音声枠の飽和による破棄が起こり得る。

## 自動検証

`npm test` は以下を確認する。

- 3航路の決定論的コンパイル、閉路境界、バンク・高度・勾配、ほぼ一定の速度。
- 不正座標、点数超過、短い線、極端な高度への応答。
- 343mの既知距離、遅延倍率、移動した観測者、Doppler制限、二重到来防止。
- 開始余白、飛行中到来、周回後の余韻、次周、Pause、Undo、Reset。
- 航跡・ログの上限、演出JSONの値域。
- 複数機の時刻・位置の再現、最後の機体の余韻まで待つこと、機体間で発音IDを混同しないこと。
- 音量配分の上限、注目変更で飛行状態が変わらないこと、字幕の優先・間隔・期限・無効化。
- 共通JSONの往復と不正入力、A/Bの通過・閉路・速度、シードの再現、傾きの追従、高度・勾配制限、機体と航路を一緒に適用する際の失敗時復元。
- 機体の進行方位と北0°の整合、観測で状態を変更しないこと、待機・終了・Pause・追加機プレビューの情報。

`npm run test:browser` は実際のクリック、ドラッグ、描線、保存・再読込を使う。編集・飛行・到来・一時停止・再周回・観測地点・音設定・画面幅を確認し、`output/browser` にスクリーンショット、ログ、結果を残す。

`npm run test:airspace` は3機の時差／同時開始、全機の音出力、注目変更、音声バスの実ゲイン、全機の終了と再周回、字幕ON/OFF、リセット、狭い画面を確認する。`output/airspace` に記録。Web Audioのゲインは、音声を継続して再生しながら検証する（入力がないノードのAudioParamは評価が止まる場合がある）。

開発環境の `window.advanceTime(ms)` で決定論的に進める。`window.render_game_to_text()` は現在フェーズ、位置、音到来、表示状態、音声ノード数をJSONで返す。時間を進めるテストは、実時間の音声再生の正確性や音の心地よさを保証しない。

`npm run test:workshop` は寸法・配置、2点地図のクリック、シードの再現、JSON適用・不正値の拒否・書き出し、保存復元、飛行、既存の高度編集、狭い画面、繰り返し編集時のGPUリソース数を確認する。`output/workshop` に記録。

`npm run test:observation` は実際のクリック・ドラッグ・タッチ・キーボードで機体情報を検証する。3機の選択、待機・終了・Pause、視線と進行方位の分離、音の注目を維持すること、Reset・機数変更、リサイズ、狭い画面を確認し、`output/observation` に記録する。クリック判定は移動6px以内。画面に投影した選択範囲は半径16〜80pxで、タッチ時は最小22px。厳密な遮蔽判定はない。

`npm run test:evolution` は3機の音到来待ち、周回間のPause、自動継続とキャンセル、選択機の継続、生成中の保存値保持、6周のGPUリソース数、選んだ航路の保存・再読込、元への復帰、キーボード、狭い画面を検証し、`output/evolution`に記録する。非表示タブのハンドラーは、headless環境で`document.hidden`を一時的に模擬して検証する。

`npm run test:offline` は配布版で保存→通信遮断→再読み込み→設定復元→実時間の飛行・音声出力・機体情報→自動で第2周へ→第2周の音到来・出力→再接続を確認する。早送りは使わず約2分かかる。既定URLはpreviewの4173番。`SOUND_TRAIL_URL`を指定すると公開URLでも実行できる。

## 人による受入確認

`npm run test:vr` はIWERでQuest 3を模擬する。入場拒否・床取得失敗からの復旧、2眼、頭の移動とAudioListener、トリガー・グリップ、開始・音声・停止、非表示・復帰、退場・再入場、複数機と観察地点を確認する。配布にIWERは含めない。検証結果は`output/vr`。実機の6項目は[Quest VR](quest-vr.md)で別に管理する。

1. ヘッドホンを装着し、音量を低めから調整する。
2. 大きな旋回を飛ばし、最初は音がなく、過去の位置から徐々に音が届くことを確かめる。
3. 一周を眺め、機体と航跡のどちらへ目が向いたかを記録する。
4. 草原と丘の上で同じ航路を比較し、聞こえる方向・音量・到来の差を確かめる。
5. 一筆描画の結果が、提案した線の特徴を十分残しているかを確かめる。
6. もう一周を自然に見たくなるか、編集と観察の時間配分が心地よいかを記録する。

v0.1についてユーザー1人から「音の方向を探して向く瞬間が楽しかった」との感想を受領。[試遊の記録](playtest-log.md)に保存した。上記全項目の受入、v0.2の複数機の聴感、モバイル実機の性能、独立WebXRの実機体験・共有セッションは未検証。自動テストの合格と分けて扱う。

v0.3の試遊では、形状を変えた違いが分かるか、A/Bの操作から意図した飛び方を作れるか、追従時間の差に重さを感じるかを追加確認する。これらの聴感・体感はまだユーザーに確認していない。

v0.3.1では、機体を選ぶ操作が分かるか、情報カードを開いても空を見る楽しさが残るかを確認する。機体視点は未採用の候補。段階と確認項目数は[進捗と段階](progress-overview.md)で管理する。
