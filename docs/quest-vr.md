# Quest 3 — 空に立つ、最初のVR試遊

更新: 2026-09-15 / v0.6.0 PCから空を持ち込む・見え方と操作の改善

## 今回の範囲

**v0.8.0追記:** 共同編集の試作を追加。[共有する空](shared-sky.md)では、招待URL／QRでPCと同じ部屋に入り、VR内で機体・航路・高度・速度・2地点を編集し、発進・次便の予約ができる。音の休憩は自分だけに適用され、共有時刻は止まらない。以下は従来の単体版の手順。ARは[2モードの設計](ar-modes.md)を記録した段階で、まだVRの透過表示として提供していない。

ユーザーが推奨方向「Quest 1台で地上から見上げて聴くVR」を選択し、試す機種をQuest 3と確認した。PCで作る機体・航路・音伝播を、独立WebXRの1人用VRで観察する。試遊機種はQuest 3だが、対応機種の保証や性能評価はまだ行っていない。

VR入退場、頭の移動・向きに追従する音、コントローラーでの開始・休憩・再開・機体選択・消音、周回継続を実装。v0.5.1からVR内の「音の設定」で音量・出力設定・全体ミックス・選択機を強める操作ができる。航路編集、機数・周回条件の変更は入場前のブラウザ画面で行う。機体情報の選択と音の注目機は独立しており、選んだだけでは音量配分を変えない。

## 最初の5分

PCで作った機体・航路は「この空をQuestへ渡す」からURL／QRにできる。[XRQRを含む受け渡し手順](sky-transfer.md)を参照。取り込みはVR入場前に行う。

v0.6.0では機体・操作盤がない空へ向けてトリガーを押しても選択を外せる。PCは空の空白をクリック／タップする。視点を回すドラッグや、操作盤の空き部分は解除しない。前回追加した解除ボタンは実機で動作確認済み。

音航跡は色を暗くする代わりに透明度を下げて消す。線・波紋の濃さも抑え、遠くの機体にも視界上の最低限の余白を設ける。機体直後に出る飛行機雲の追加は別の構想メモ。

v0.5.2では、通常の操作盤・音設定のどちらからも「選択を外す」を押せる。情報と選択マークを消し、音を「空全体を聴く」に戻す。飛行・航路・休憩状態は保つ。解除後は機体を選び直すと再び個別に強められる。PCでは機体情報の「選択を外して空全体を聴く」が同じ操作。PCの×・Escapeは従来どおり情報だけを閉じる。

線と音の波紋は、見ている機体の周辺でなだらかに薄くなる。軌跡の位置・音の到来は変わらない。選択中の機体だけでなく、飛行中の全機体に適用する。

1. Quest 3のブラウザで[試遊URL](https://tom7x7.github.io/airplanevoice/)を開く。
2. 最初は「1機」「大きな旋回」「草原」。繰り返し眺めるなら「周回ごとに変化して飛び続ける」をONにする。
3. 「VRで空に立つ」を押す。入場時にブラウザの音を有効にする。飛行中に入場した場合は、いったん休憩状態になる。
4. 正面の操作盤をコントローラーで指し、トリガーで「この航路で飛ばす」または「飛行を再開」を選ぶ。
5. 頭を左右へ向け、少しかがみ、音から機体を探す。機体を指してトリガーを押すと、速度・進行方位・距離が操作盤に表示される。操作盤のST-01等からも選べる。
6. 操作盤が見つからないときはグリップを押す。今の正面へ操作盤を呼び直せる。
7. 「ひと休み」で時計と音を止める。ヘッドセットを外す／システム画面へ移るときも休憩する。戻った後は明示的に再開する。
8. 「VRを終了」でブラウザへ戻る。終了時は休憩状態を保ち、入場前の観察地点へ戻す。

移動スティックや機体に乗る視点は追加していない。自分の立つ場所を保ち、まず見上げる体験を確かめる。編集データは各ブラウザに保存されるため、PCで作った設定がQuestへ自動で同期されるわけではない。

### 音の再試遊

1. 初期設定は「本体スピーカー向け」。ブラウザの「音・表示の設定」でも切り替えられる。初期アプリ音量は35%、最大70%。本体の音量は別に調整する。
2. VR内で「音の設定」→「空全体を聴く」。機体が飛び始めても、音が届くまで数秒の間がある。
3. 機体ボタンの下のバーは、各機体の位置音・音量配分後の内部信号。バーが動くのに聞こえにくいかを確認する。バーの長さは距離・音量配分で変わる。
4. ST-02またはST-03を選び、「音の設定」→「ST-02/03を強めに聴く」で比較する。ほかの機体は小さく残る。「空全体を聴く」で戻す。
5. 音量±5、ヘッドホン向け／本体スピーカー向けの切り替えを試す。「空の操作へ」で戻る。聴き方を変えても、航路・飛行時刻・音の到来時刻は変わらない。

最初に聞きたいのは「空に立つ感覚」「音から探す楽しさ」「操作で詰まった場所」。見た目の細かな仕上げや新機能は、この結果を受けて優先順位を決める。

## 実装と検証の境界

- Three.jsのWebXRManagerとReact Three FiberのXR描画ループを使用。単位は1m、参照空間は`local-floor`。床の原点を入場前の観察地点に合わせる。
- 音と伝播計算には`XRFrame.getViewerPose()`の頭の中心を使用。左右どちらかの目のカメラを耳の座標に流用しない。頭の位置を更新してから音到来を計算する。
- 映像は左右の目ごとに描画する。PCのドラッグ視点・ズームをVRへ毎フレーム上書きしない。
- 操作盤は空間に固定し、グリップ操作時だけ呼び直す。手追跡用UIやARパススルーは未実装。
- 機体の選択には機体寸法と角度に応じた余白がある。厳密な機体表面・遮蔽物の判定ではない。
- 消音は音の出力を切り替える。休憩は時計も停止する。頭の追跡が失われた場合も休憩し、勝手に再開しない。
- 描画解像度倍率1、周辺部の解像度を下げる設定0.5、既存の距離による細部省略・窓の一括描画・音声最大18本を使用。最適値は実機測定後に判断する。
- 直近最大600フレームの描画間隔p50/p95を体験ログへ保存する。GPU時間や実機FPSの保証値ではない。休憩・装着解除後の空白は通常フレームの集計に含めない。
- VRの自動確認はMetaのIWER 2.4.0でQuest 3を模擬し、実際のWebXRセッション、左右眼、入力イベント、Web Audioの値を検証する。IWERは開発依存だけで、配布アプリに含めない。
- ユーザーによるQuest 3実機試遊があり、v0.5.1で3機の聴取成功を受領。開発側からの端末測定、音の定位・フレーム性能の詳細、v0.5.2の軌跡と解除操作の実機評価は未確認。通常ブラウザのオフライン試験を、Questでのオフライン起動成功とは扱わない。

## 自動検証の再実行

```sh
npm run dev
# 別ターミナル
npm run test:vr
```

PowerShellで配布版を対象にする場合:

```powershell
$env:TEST_URL = 'http://127.0.0.1:4173/'
$env:VR_OUTPUT = 'output/vr-production'
npm run test:vr
Remove-Item Env:TEST_URL
Remove-Item Env:VR_OUTPUT
```

`output/vr`に画像と検証結果を保存する。配布版では開発用の時間送りを使わず、初周と複数機の音を実時間で確認する。周回の加速チェックは開発版のみ。

技術参照: [Three.js WebXRManager](https://threejs.org/docs/pages/WebXRManager.html)、[MDN requestSession](https://developer.mozilla.org/en-US/docs/Web/API/XRSystem/requestSession)、[Meta IWER](https://github.com/meta-quest/immersive-web-emulation-runtime)。
