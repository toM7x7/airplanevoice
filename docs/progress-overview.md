## 今回の小さな作業単位

**マルチ初回試作：4/5を実装・自動確認。5はクラウド配置済み、PC＋Quest実機での試遊待ち。**

1. **同じ部屋へ入る**：永続化された設定・版を、別のブラウザと招待URL／QRで共有。
2. **双方から編集する**：PCの画面とQuest模擬のレイ操作から機体・航路・高度・速度・A/B地点を変更。同時変更は版番号で競合を検出。
3. **同じ飛行を見る**：共通開始時刻、途中参加、各端末の音、個人休憩、再接続を自動確認。
4. **次を作って飛ばす**：飛行中の設定を固定し、下書きと予約便を分離。二重発進・古い編集の上書きを防ぐ。
5. **クラウド＋実機で試す**：指定アカウントのWorkers Freeに配置。PC＋Quest 3での双方向操作・音・見た目のずれを人が確認する工程は残る。

コア・接続クライアント88件、従来PC操作20項目、従来VRの配布版模擬23項目が合格。共有のローカル通し確認では独立した2ブラウザ、実際のWebSocket、QR復号、VR操作盤、予約・取消、再接続を確認した。端末が長く休止した後に古い時計補正を使わない回帰確認も追加。詳細は[共有設計](shared-sky.md)、起動手順は[公開・配置](deployment.md)。

Cloudflare公開版の共有通し確認10項目も合格。位置比較は同じ便の開始時刻・チェックサムの一致に加え、逐次取得した2端末の位置差が約9.4mだった。これは模擬ブラウザの描画間隔・取得時間差を含むサンプルであり、実際の同期誤差やQuestでの許容値の測定結果とはしない。

ARは[基本観察と展示会案内の2モード](ar-modes.md)を記録した段階。背景の透過表示、会場測量、管理操作、MCP・LLM接続の実装完了には数えない。

演目作成の複雑さの見直しを、作る体験自体の撤回として扱わない。旅客機を眺める体験と共同制作を両立させる。ミニチュアとLLMは候補として保存し、この試作の完了条件には追加しない。

## 次の試遊で聞くこと

- 自動継続を2〜3周眺めたとき、変化が自然で、もう少し見たいと思えるか。
- 気に入った周回を残す操作と、周回間の余白が体験に合うか。

- 機体を押して情報を見る操作が自然に分かるか。
- 方向の数値・コンパスが「どう飛んでいるか」の理解に役立つか。
- 情報を開いても空を見る楽しさが残るか。
- 機体視点が欲しくなる場面が実際にあるか。これは追加採用の検討用。
