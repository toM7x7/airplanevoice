# 動きの比較 第2稿

**2026-09-18評価後：この3案は通常UIとして未採用。** 実際の操作盤は[短い開閉](control-components.md)へ更新した。以下の動画と共通動作の記述は比較時点の履歴。現在のPC／XR操作部品はこの演出を使用しない。

2026-09-18 / ローカル試作。公開版は未更新。

## 前回からの修正

ユーザー評価：3案が同じに見える、ふわっとした変化が弱い、VRの動きが見えない、録画がカクついている。前回の機能試験が通っていても、映像や演出の品質が満たせたとは判断できなかった。

| 案 | 今回変えた動き | 見る場所 |
| --- | --- | --- |
| 翼がひらく | 項目を畳んだ状態から左右に回転、浮き上がって整列。背景面は後から出る | 開始約1.0〜1.6秒 |
| フライバイ | 機影と3本の航跡が横切り、項目が横から順番に現れる | 約1.0〜1.8秒 |
| 音の到着 | 時間差の輪が広がり、操作面と項目が中心から育つ | 約1.2〜1.9秒 |

開く1.65秒／閉じる0.65秒。**差を選ぶために強めにした比較値**で、通常利用の速度を確定してはいない。採用後は日常の開閉を短くする案も評価する。画面や頭の位置は動かさず、操作部品の範囲で演出する。

## 試す入口

- `http://127.0.0.1:4893/review-board.html`：PC3本・VR3本の60fps動画。同時再生、半速、大きく見る。
- `http://127.0.0.1:5173/?ui=motion`：軽量な動作模型。PC／VR、3案、フレーム単位のシーク、明示したときだけ音付き再生。
- `http://127.0.0.1:5173/?ui=components`：実際の飛行と組み合わせたDOM・WebXR操作部品。同じ案をもう一度押すと再演。
- `motion-film`：Remotion Studioの編集元。

比較動画は`MotionArtwork.tsx`をRemotionでフレームごとに描画。PC実装／WebXRのCanvas描画／映像は`menu-motion.ts`の項目位置・回転・拡縮・透明度を共用する。レイアウトと描画方式は各環境に合わせるため、**動画は実機キャプチャではない**。VR動画の手は操作イメージを説明する図形で、実際の手トラッキングや押下判定の記録ではない。

## 実装上の扱い

- 動画は1280×720、60fps、540フレーム、映像9秒。音声のAACパディングによりコンテナの長さは約9.05秒になることがある。
- 各フレームは時刻から計算。録画負荷に依存するPlaywrightの画面録画を演出比較の納品方法から外した。
- 「動きを減らす」で即時切替。途中で閉じれば現在位置から戻る。演出待ちで飛行を止めない。
- XRの移動中の項目は押せない。バーは開閉中も使用できる。直接タッチも開き切った位置だけで受ける。
- 低い風音とハムを合成した小さな演出音を作った。音付き比較のみで再生し、実際の機体のエンジン音を置き換えない。
- `?ui=motion`の表示を隠す／停止すると音も停止。マイク、会話AI、部屋への命令は使わない。

## 検証と未確認

映像ファイルの全540フレームをデコードし、60fps・映像9秒・音声トラックを確認。さらに開く途中の操作盤領域97フレームが97種類であることを検査。結果は[verification.json](concepts/2026-09-18-motion-v2/verification.json)。これはカクつきやすかった旧録画のような重複フレームの検査で、Questのフレームレート測定ではない。

ユーザーの好み、表示を邪魔しないか、素手での疲れや距離感は未確認。まず比較で方向を選び、Quest 3単体、その後Quest 3＋2の位置合わせへ進む。実機T1〜T4は0/4のまま。

## 再生成

```powershell
npm --prefix motion-film ci
node scripts/build-motion-audio.mjs
npm run render:motion
npm run test:motion-films
npm run test:motion
```

動画ソース変更後は該当する動画を再生成する。`node scripts/render-motion-films.mjs VR-trail`のように指定可能。`test:motion-films`は同梱Windows FFmpegを使う。再生確認はローカルHTTPサーバーで行う。
