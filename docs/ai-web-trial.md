# 通常画面のAI操作案内 — 2026-09-18

## 現在の入口

Cloudflareの通常画面に「AI案内」を組み込む。`/?ai=guide`で直接開ける。以前の`?ui=components&ai=trial`も通常画面へ移す。API・Durable Objectの内部名は互換性のためtrialを維持する。独立した試用画面を使う必要はない。

OpenAI / TypeSafeのキーはWorkerのSecret。通常画面のボタン操作にAIは不要。AIを開いただけで会話や観察を自動開始しない。運営用の入場キーと1接続の管理を維持し、回数・会話時間・試用期限の上限は撤去した状態を保つ。

## 通常操作への接続

| 依頼 | 実際の処理 |
| --- | --- |
| 「音量の変え方を教えて」 | 音と表示の設定を開き、スライダーに強調枠。音量自体は変えない |
| 「音量を25にして」 | 端末の音量を25%へ変更し、値を確認して結果を返す |
| 「3機にして」 | 単体の編集画面で機数を変更。飛行中・演目編集中は変更しない |
| 「飛ばして」「ひと休みして」 | 単体の飛行エンジンを開始・停止。共有の飛行予約はこのツールから実行しない |
| 「ST-02を見せて」 | 登録済み機体の情報を表示。飛行中に見える機体ならそちらを向く |
| 「空全体を聴く設定にして」 | 複数機の聴き方を変更 |
| 「設定を開いて」「実験室を開いて」 | 対応する既存パネルを開く。飛行中や演目を壊す編集切替はしない |

音の初回再生がブラウザで許可されていない場合は、音ボタンを示して本人のクリックへ戻す。メニューとAIは同じアプリの設定・飛行エンジンを操作し、別の値を持たない。共有画面では端末の音量・再生・機体情報・設定への案内までを接続した。共有する航路・飛行予約の変更は権限とackを結ぶ後続作業。

案内や操作の際は会話パネルを小さく畳み、強調対象を隠さない。会話接続と音声プレーヤーは保持し、「案内を開く」で戻る。「閉じる」は会話・観察を終了する。タブの切替だけでは会話を終了しない。XR内の強調表示・ツール操作は未接続で、今回の通常画面はブラウザ画面を指す。

## ツールの流れ

GPT-Liveのclient delegation → 軽量LLMのResponses API function calling → `control_sky` → 許可された操作ID・値を検証 → ブラウザで実行 → `/api/ai/action-result`で状態を報告 → 結果をGPT-Liveに返す。

- `mode=guide`は場所の強調、`mode=apply`は利用者から明確に依頼された変更。曖昧な初期設定の相談は、一つずつ提案・確認する。
- 操作ID、値の範囲、現在の画面の機能、現在の機体、編集可能な状態を実行前に検査。任意のコードや任意のDOMセレクターをモデルから実行しない。
- 操作にはIDと30秒の有効期限を付ける。これは古い指示の適用防止であり、会話の時間制限ではない。重複した結果を受けても二重操作・二重読み上げをしない。
- 設定値が変わったという画面の結果を受けてから、アプリの定型文で完了を伝える。未適用・期限切れ・結果不明は成功としない。
- 完了文を作るためだけに追加LLMを呼ばない。音声のツール命令待ちは800msごとの状態取得、飛行情報の更新は5秒間隔。これらは有料推論ではない。

## TypeSafeの観察をどう使うか

**観察 → 注目点 → 利用者が選ぶ次の行動**を初回の使い方にする。距離と姿だけを文章で列挙する状態から、体験につながるカードへ進める。

1. エンジンが、飛行状態、距離、接近・遠ざかりを表す速度、届く前の音の数、端末内の音声信号を計算する。
2. アプリが事実に基づく候補を作り、TypeSafeが約10秒ごとに注目点を選ぶ。例えば「ST-02が近づいている」。
3. カードに「ST-02を見る」「音の聴き方を教えて」「飛ばし方を教えて」を付け、押したときだけ通常操作へつなぐ。
4. 同じメモをGPT-Liveへ渡し、利用者から質問されたときの説明に使う。

端末内の信号レベルはマイクで測った聴こえ方ではない。現在は生の音声波形、音色の意味、音の文法、ユーザーの感情をTypeSafeへ渡していない。音作りの次段階は、低音の厚み・通過の前後・複数機の重なりなどの特徴を定義して候補にすること。自動ミキシングや航路調整は、目的・許容範囲・元へ戻せる操作を別途設計してから接続する。観察だけで設定を勝手に変更しない。
