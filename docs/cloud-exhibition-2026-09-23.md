# ひとつの展示空間とクラウド格納庫

更新: 2026-09-23

## 使い方

入口: https://airplanevoice.pages.dev/?shared=1

1. PCもQuestも同じURLを開く。部屋の作成・招待キーの入力は不要。
2. PCの「つくる」で編集し、「クラウド格納庫に保存」を押す。
3. Questの「保存した機体を呼び出す」で同じ名前を選ぶ。VR内でも変更して「クラウドに保存」できる。
4. 「この機体を飛ばす」で共有の空へ送る。既に飛行中の機体には編集を適用せず、次の出発から反映する。
5. 以前この端末だけに保存した機体は、格納庫の「この端末の○機をクラウドへ保存」で移す。元の端末内データも残る。

別のURL（旧Workers URL、GitHub Pagesなど）のブラウザ保存は自動では読めない。そのURLで格納庫ファイルを出力し、新しいURLの「機体のバックアップ・以前のURLから読み込む」から読み込み、クラウド保存する。旧招待部屋も従来どおり開ける。

## 保存と動作

- 固定のDurable Objectに格納庫・飛行予定・展示の繰り返し設定を保存。PCとQuestは同じSQLiteデータをWebSocket経由で共有する。
- 展示用の新規固定空間には8時間の終了期限を設けない。ブラウザを閉じてもデータを保持し、サーバーのアラームで飛行を繰り返す。
- サーバーは飛行の設定と時刻を管理する。3D映像・空間音響の計算は各端末で行い、クラウドから動画を配信する構成ではない。
- 初期状態は既定の機体が自動飛行する。クラウド格納庫への保存後は、保存した機体を順番に飛ばす。最後の機体を外した場合は既定の飛行へ戻る。
- 運営画面から繰り返しを止められる。止めても格納庫は消えない。
- 保存の成功応答を受けるまでは保存済みにしない。通信断では下書きを維持する。
- 読み込んだ後に別端末が同じ機体を更新した場合は上書きを拒否する。クラウドから読み直して確認する。
- 新しいアカウント・DBサービスの契約は追加していない。既存のCloudflare Workers / SQLite Durable Objectsを使用する。

## 現在の範囲

- クラウド格納庫24機、同時飛行3機、同時接続4台。多数の保存機体は順に登場する。
- 今回は展示用の共同格納庫。URLから入った参加者は共通の機体を呼び出して保存できる。所有者別の非公開格納庫・アカウント権限は追加していない。
- 保存は明示的に行う。編集途中のつまみ操作は他端末へ逐次送らない。
- 「同じ空の同期」と「現実の机に対する位置合わせ」は別の処理。今回の変更で物理的な位置合わせを自動化したわけではない。
- 従来の個別部屋作成は `?shared=1&private=1` に残す。既存の `room=...#key=...` の招待URLを固定空間へ書き換えない。
