# 音の出力検証 — Quest実機の感想から

更新: 2026-09-15 / v0.5.1

## 分かったことと、まだ分からないこと

ユーザーはQuest 3本体スピーカーで1機・3機を試遊し、「1機は小さい、3機では他機が聞こえない気がする」と報告した。3機時は「空全体を聴く」。注目モードの選択だけでは説明できない。

旧版の比較測定では3機すべての信号が同じ時間に出ていた。したがって「コード上で2機目以降を再生していない」という状態は今回のPC測定で再現していない。一方、機体間の距離・音量差は大きい。Questの出力特性、本体音量、現地ノイズ、音の似通い、ブラウザ状態を含む原因はまだ確定していない。

## 比較方法

大きな旋回、草原、音量35%、全体ミックス、開始間隔0秒。シミュレーション18秒まで進めた後、実時間で再生を継続し、約4.5秒・45サンプルを採取した。飛行計算の時間送りだけで音の検証を終わらせない。

各機体のPannerNodeとミックスゲイン通過後、および最終DynamicsCompressorNode通過後に、左右チャンネルを分けて波形を採取する。左右を先に足すと位相によって小さく見えるため、各チャンネルの二乗平均からRMSを求める。dBFSはアプリ内デジタル信号の大きさで、耳元の音圧ではない。

| 比較 | v0.5.0 | v0.5.1スピーカー向け・今回の測定 |
| --- | --- | --- |
| 1機・最終出力RMS | 約−30.4 dBFS | 約−23.6 dBFS |
| 3機・最終出力RMS | 約−33.4 dBFS | 約−26.1 dBFS |
| 3機とも同時に信号があったサンプル | 45/45 | 45/45 |
| ST-03とST-01の機体バスの差 | 約−9.4 dB | 約−9.4 dB |

実時間の描画・採取タイミングにより値は少し変わる。この調整は全機を同じ音量に揃えるものではない。位置による差を残しつつ信号を持ち上げ、機体別の聴き比べを用意した。v0.5.1がQuestで聞きやすくなったかは再試遊で確認する。

## 変更

- 初期出力設定を「本体スピーカー向け」にした。距離減衰の基準を350→550m、減衰係数を1.4→1.1へ変更し、850Hz・Q0.65の成分を5dB補う。これは体験用の音響演出で、機体の物理音圧を校正した設定ではない。
- 「ヘッドホン向け」で旧版の距離減衰・音色に戻せる。設定変更は進行中の短い音を切らず、音色は150msの時定数、距離設定は新しく鳴る音から反映する。
- マスター音量35%、最大70%、既存コンプレッサー、6音/機・全体18音の上限を維持。
- VR内の音設定で全体・選択機を強める・音量±5・出力設定を選ぶ。機体情報を選ぶ操作だけでは音量配分は変えない。
- メーターは最大3機と最終出力、左右別の波形を100ms以内に重複して読み直さない。VR描画では200ms間隔で表示更新。ログには音声状態、各機体の再生数・同時再生数、出力設定・音量・信号値を保存する。外部送信はしない。

## 再実行と範囲

開発サーバー起動後、`npm run test:audio`。1機・3機、近距離の3機に音量上限と高頻度発音を与える負荷条件、ヘッドホン設定を確認する。消音・音量0・音量復元・停止を、実際の最終波形でも確認する。

近距離・最大音量・高頻度の今回の採取ではピーク約0.62、全体18音以下だった。これは今回測定した入力の結果で、あらゆる編集条件で音割れがないという保証ではない。

結果は`output/audio-output/`。旧版の記録は`baseline-v0.5.json`、新版は`speaker-current.json`。旧版採取のフラグはv0.5.0のチェックアウトでのみ使う。通常のテストは外部ファイルの旧版結果を必要としない。

VRでは`test:vr`で、3機の信号が同じサンプルに存在することと音設定操作を確認する。実機での聞こえ方は[Quest VRの再試遊](quest-vr.md)と[試遊記録](playtest-log.md)へ記録する。

技術参照: [W3C Web Audio API](https://www.w3.org/TR/webaudio/)、[DynamicsCompressorNode](https://developer.mozilla.org/en-US/docs/Web/API/DynamicsCompressorNode)。
