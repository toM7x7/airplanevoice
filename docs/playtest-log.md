- VR内とQuestブラウザ側の操作、QR経由の入口を整えたい。現実空間が見えるAR化と安全面、音の通り・聞きやすさも今後の課題。

**次の再試遊**: v0.5.1のスピーカー向けで1機→3機・全体ミックスを比較。VR内の「音の設定」からST-02・ST-03を個別に強め、音が来ているか／違いが分かるかを確認する。バーが出ても聞き取りづらい場合は、その機体・観察地点・アプリ音量・本体音量を記録する。音の修正後の実機評価はまだ受領していない。

## v0.4.0 / 次の試遊で確かめること

「周回ごとに変化して飛び続ける」をONにし、2〜3周を眺める。自動テストの合格とは別に、次を確認する。

- 何も操作しない時間にも、空や機体を見ていたくなるか。
- 変化が自然に感じられるか。機械的な繰り返しや違和感が出る場面はあるか。
- 気に入った周回を残す操作が、観察を中断したくなるほど役立つか。
- 周回間の余白が気持ちよいか。機体が途切れず空域を移る方式を試したいか。

天候や他機との関係による生成、AI、音の分布図は今回の試遊対象に含まない。追加キーワードの採否は[構想キーワードの索引](idea-atlas.md)から必要な候補を選んで比較する。

## 2026-09-15 / v0.3.1 / 機体を見つけて観察する流れ

- 「グッド」「いい感じ」「飛行機のキャッチアップの仕方もいい感じ」との感想を受領。飛ばした後の観察の工程を肯定的に評価。
- 固定の飛び方を眺める土台から、航路を作り、動的に変化する体験を育てたい。
- 開発・試遊はまずPC中心。スマホは後で試す予定で、実機評価済みとは扱わない。
- 音の分布を見るレイヤー、AIの観察役の切り替え、録画による予備再生は[思いつきメモ](idea-notes.md)に保存。

機体を見つける操作への定性的な肯定。速度・方位の表示精度、すべての操作の受入、他の人での再現性を確認した結果ではない。次は「変化を作る→飛ばす→違いに気づく」の往復を比較する。

## 2026-09-15 / v0.1 / ユーザーによる試遊

**観察された発言**

- 「こういうのがまさに欲しかった」
- 「音が立体音響っぽくなってて、どっちにいるんだろうって向く瞬間が、すげえ楽しかった」
- ARで体験すること、機体・音・空を磨くことへの期待。
- 複数Questで同じ空を共有したい。複数の機体が鳴るときの調整も必要という意見。
- AIは「管制官のような案内・調整役」と明確化。

**解釈**

音から機体を探す行動に、このユーザーが求める楽しさがある。次の磨き込みでは、発見のきっかけになる音と、見つけたときの機体の存在感を優先する。

**記録の限界**

1人の定性的な感想。使用ヘッドホン、出力音圧、音色の正確さ、他の人での再現性は未測定。Questの実機評価ではない。

## v0.2 / 次の聴き比べ

コード・ブラウザの検証結果は[開発と検証](development.md)と`progress.md`に記録する。以下の人による試遊はまだ実施していない。

| 比較 | 見たいこと |
| --- | --- |
| 1機 → 3機、同時開始 | 音が増えても方向を探したくなるか。耳が疲れないか |
| 3機、同時 → 8秒 → 16秒間隔 | 空のにぎわいと聴き分けのバランス |
| 空全体 → 注目機 → 別の注目機 | 背景機の存在を感じながら、目当ての機体を追えるか |
| 管制字幕OFF → ON | 案内が場面の理解に役立つか。空から視線を奪わないか |
| 草原 → 丘 | 同じ予定で、方向・遅れ・距離感に違いを感じるか |

試遊後は「良かった瞬間」「邪魔だった瞬間」「次に一つ変えるなら」を短く残す。自動テストの合格を、楽しさや音の心地よさの評価に置き換えない。
