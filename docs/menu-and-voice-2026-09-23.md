# メニューの固定・名前で呼び出すAI案内

## 今回の変更

### VR / ARの操作盤

- 手とコントローラーの認識が切り替わったとき、編集から飛行へ移ったときの自動再配置を廃止。
- 左右に緑の取っ手を配置。指なら近づけてつまむ、コントローラーなら取っ手を指してトリガーで移動。離すとその位置で固定。
- 上端の見出しや通常のボタンを押す操作は、移動操作として扱わない。
- 手の追跡が戻ったときは、一度指を開いてからつまむ必要がある。手を離した直後の接触記録は、4.5cm以内に手が残る場合だけ有効。
- 「手元へ呼ぶ」とコントローラーのグリップは、明示的な呼び戻しとして残す。手のsqueezeイベントでは呼び戻さない。
- AIがメニューを開く場合も、既存の位置を保つ。最初の配置は手でも届く距離に統一。

位置は端末内の操作盤だけの情報。共有する飛行・地図・他の利用者の座標は変更しない。

### GPTライブの機体名と操作

会話の判断側に、同じ画面から以下の構造化情報を渡す。

1. 格納庫：保存機体のID・ユーザーが付けた名前・保存場所。
2. 下書き：編集中の機体ID・名前・形・音設定・未保存状態。
3. 空：飛行枠の内部IDとユーザーの機体名、距離・飛行状態・音の情報。
4. 操作画面：PC / VR / AR、格納庫 / 編集 / 観察、選択中の項目、切り替え確認中か、出発できるか。
5. メニュー：実装と共通の形・色・音の選択肢、移動先、許可されたコマンド。

YAMLを別に手入れする方式ではなく、TypeScriptの操作定義からJSONのメニュー情報を生成する。ST-01等は内部の飛行枠であり、会話ではユーザー名を使うよう指示する。同名の機体は勝手に選ばず確認する。

| 話しかけ方の例 | 画面で行うこと |
| --- | --- |
| 「飛行機を飛ばしたい」 | 対象が不明なら格納庫を開いて名前を尋ねる |
| 「そらを呼び出して」 | 名前から実在する格納庫IDを選び編集画面へ。未保存なら確認で止まる |
| 「機体の音を変えたい」 | 音の編集画面を開いて希望を尋ねる |
| 「重く深い響きにして」 | 下書きの音設定を変更して実行結果を返す |
| 「この機体の飛ばし方を教えて」 | 出発ボタンを強調。保存・出発は本人が押して確定 |

上記は会話の意図と操作の対応仕様。文言の聞き取りとLLMの選択精度は実会話で確認する。各操作は実行後の画面状態を照合してから完了を返す。未保存の切り替え確認中にAIが変更を重ねる操作は拒否する。

GPTライブは既存の `/v1/live/sessions` とクライアント委譲を継続。会話・バックエンド判断・画面での実行結果を分ける。参照：[OpenAI Live delegation](https://developers.openai.com/api/docs/guides/live-delegation)。新しい会話指示は会話を終了・開始し直すと反映される。
