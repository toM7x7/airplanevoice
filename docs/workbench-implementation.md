# 格納庫・編集・観察の実装記録

2026-09-22

[Cloudflare公開版](https://airplanevoice-shared-sky.tomohaya-falcon-aramaki.workers.dev/?shared=1)へ反映済み。Version `b6d4c396-68d9-44ef-a841-c3542b27c5bc`。PCの主要フロー10項目は公開ブラウザでも通過。[公開記録](release-2026-09-22.md)。ローカル8787も同じ配信版。

## 今回の更新

- **格納庫**: 保存した機体を名前・色・寸法で一覧表示。選択中の模型を大きく表示し、編集と飛行へ進む。
- **つくる**: 左の「形 / 色 / 音 / 航路 / 名前」で対象を選び、右だけを切り替える。保存と飛行は下端。基本形・尾翼/エンジンの色・合成音・航路・日本語名を編集できる。
- **背景比較**: 同じ模型の姿勢と設定を保って「格納庫 / 空港 / 空」を切り替える。コードで構築した背景。自分の画面だけに作用し、部屋の設定・飛行時間は変更しない。空背景は比較用の表示で、実際の高度を変える機能ではない。
- **空を眺める**: 飛行の受付後にPCを観察画面へ移す。格納庫・再編集・音量の小さな操作列。機体を押すと従来の飛行情報も見られる。編集へ戻ってもCanvas・部屋接続・既存の飛行を維持。
- **部屋・運営**: 共有設定・会場設定・従来の運営操作を集約。
- **機体切替**: PC/XRとも選んだ模型を確認してから呼び出す。未保存なら「保存して切り替える / 保存せず切り替える / 続けて編集する」。呼び出しても飛行中の機体は置き換えない。PCの確認はキーボードで操作できるダイアログ。
- **XRのAI**: 認証済み端末はXR内で接続準備できる。会話・ミュート・Jev観察を個別に開始/停止。権限とキー検証は維持。通常の制作・AR切替・呼び出しでAIコンポーネントを作り直さない。
- **AIの案内先**: PCでは見えている操作を選び、制作カテゴリとボタンを強調。AIパネルは小さく畳んでも接続を維持し、編集を邪魔しにくくする。

## 確認方法

```text
npm test
npm run check:worker
npm run build
node scripts/workbench-check.mjs
node scripts/creation-model-check.mjs
node scripts/creation-check.mjs
```

`workbench-check` は `SHARED_URL` に指定したローカルWorkerを使用。`creation-check` はPCと模擬Questを同じ部屋に入れて、実際の保存・共有・飛行とXRレイ操作を確認する。AI応答・Jevはブラウザのfixtureを使用し、外部の有料APIは呼ばない。証拠は `output/workbench/`。通常のローカル8787とは別のテスト用部屋DBで実行し、部屋作成の頻度制限を展示用DBへ消費しない。

## 未確認・次の工程

- Quest 3実機で、AIのマイク許可・実際の会話・ピンチ操作と編集の併用。
- 実機の文字サイズ、模型のつかむ位置、AR背景との重なり。模擬XRを実機合格とは扱わない。
- XR一覧のサムネイルとカード表現、制作カテゴリの更なる簡潔化は次の磨き込み。
- 格納庫はブラウザ保存と期限付き共有部屋。恒久クラウド保管は未実装。
- 空港背景は景観。離着陸動作・途中帰還・20機同時飛行を追加した更新ではない。
- 会場マップは次段階。地点登録 → 手動位置合わせ → 地点選択による案内を、通常VR/AR体験と分けて完成させる。

## 確認の順番

1. PCで「つくる」→「色」。背景3種類を切り替え、模型をドラッグ。
2. 音を試聴し、名前を入力して「格納庫に保存」。
3. 「この機体を飛ばす」で観察画面へ。再編集しても飛行が続くことを確認。
4. Questの「VR / ARで体験する」へ入り、保存機体の切替・名前・飛行を確認。
5. 運営がAI接続を準備済みなら「AIと話す」→必要時「AIを準備する」。会話とJevを個別に操作。
