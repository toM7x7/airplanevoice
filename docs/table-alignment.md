# 展示の机を合わせる — 運営PC＋Quest 3

## 現在の展示構成（2026-09-18 更新）

運営者はPCで部屋と飛行を操作、来場者はQuest 3を1台使う。Quest 2は予備。PCとQuestの設定共有は必要だが、複数ヘッドセット同士の現実位置一致は今回の受入から外す。

「キャリブレーション」は計測・調整全体、「アライメント」は位置と向きを揃えること。「リセンター」は基準を置き直す操作。Tポーズは主に身体・アバターの校正で、今回の机合わせでは不要。

## 運営者の手順

1. PCとQuestで同じ部屋へ。PCの「机の位置合わせ・会場マップ」でA–Bの横幅、A–Cの奥行き、机の高さを入力し、共有に保存する。単位はm。
2. 運営者がQuestを装着し、机の通路側の使いたい位置に立つ／座る。
3. XRの「見え方・操作案内」→「机と会場」→「机の枠を目の前へ」。自分の正面65 cm先を手前辺とする仮枠が現れる。初期位置は調整の出発点で、実際の机を自動検出した位置ではない。
4. A・Bが手前、C・Dが奥。左右・前後は5 cmずつ、向きは5°ずつ調整。「高さの調整・配置の確定」で2 cmずつ上下できる。回転の中心は枠の中心。
5. 現物へ重なったら「この位置で使う（目視）」。これは手動配置の確認で、誤差の測定結果ではない。さらに調整すると仮置きへ戻る。「もう一度、目の前へ」で現在位置からやり直せる。
6. 「メニューを閉じて確認」で枠を見る。下のバーを指してピンチ／指で触ると再表示。「手元へ呼ぶ」はメニューの位置だけを置き直す。
7. 運営者から来場者へ交代。同じXRセッションを保ち、追跡が復帰したか確認する。Questの原点リセットや追跡喪失、再入場、机寸法の変更時は再配置する。

枠・会場の配置変換はそのQuestだけ。部屋の飛行、他端末の視点、時刻は変えない。音は配置後の実際の頭の位置から計算する。幅／奥行き30〜200 cm、高さ40〜140 cm。ABCと既存地図の互換のため、Cを左奥、Dを右奥と呼ぶ（周回順のABCDではない）。旧部屋は奥行きを横幅と同じ長さとして読み込む。

## 指とコントローラー

共有ルームでも手のトラッキングを任意要求。指してつまむか、前から指先で触れて手前へ戻す。押したまま連打しない。メニューは180 msで開き、120 msで閉じる。コントローラーのトリガーとグリップも継続。

追加の誤差測定をしたい場合のみ、「机と会場」→「A・B・Cで測る（詳細）」へ。光る玉のあるコントローラーでA/Bを取得し、Cで独立確認する。CはAから設定した奥行きだけ奥。Dは四角形の見え方を確認する補助で、4点フィッティングはしない。

# Quest 3＋Quest 2：机を基準に同じ空を見る

実装: v0.11.0の基盤＋2026-09-18の追加。手動位置合わせ・地点共有・縮小図／実寸表示に、C点の測定と端末状況の共有を追加。実機2台の精度・聴感は確認待ち。

## 2026-09-18：2台で確認するための更新

- PCの共有画面に「同期・2台の位置合わせ」、XRの「机と会場」に「共有・2台の状況」を追加。接続数と位置合わせの確認済み数を分け、各端末のA/B/C取得・確認待ち・追跡喪失を表示する。「この端末／自分」の番号で区別し、Questの機種は自動判定しない。
- **A→Bで位置・方向を求め、独立したC点を取得してずれを測る。** Cは計算の合わせ込みに使わず、共通座標の `(0, 机の高さ, −A/B間隔)` との差を測る。5 cm以内なら「重なりを確認」を押せる。5 cmは試作の判定値であり、端末の精度保証ではない。超えたら印の場所と取得位置を見直してAからやり直す。
- 接続中でも校正前なら未確認。追跡喪失・机の寸法変更・再入場で確認を解除する。45秒より古い端末報告は「更新待ち」とし、確認済み台数へ数えない。通信の往復時間は位置の誤差と別に表示する。
- 状態は既存の15秒ごとの接続確認と状態変化時に伝える。飛行設定の版・便・開始時刻は変更しない。観覧権限でも自分の位置合わせ状況は報告できる。頭・手の連続座標、マイク音声、恒久的な端末IDは送らない。
- **2台が確認済みでも、現実の同じ位置へ重なったことの実機合格ではない。** 以下のT1〜T4は実機で確認する。今回の位置合わせ取得はコントローラーで行い、指だけの取得は後続。

実装上の接続情報はWebSocketごとの一時情報として保持する。共有飛行の保存やalarmとは別。[Cloudflare公式の接続情報保持](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)。

## 地図の見方を選ぶ

PCでは「机の位置合わせ・会場マップ」→「小さな地図で見る」。XRでは「見え方・操作案内」→「机と会場」→「会場の地点へ」→「地図の見え方」。

- **小さな地図で見る**：地点全体を前方の配置図に収める。実際の図面画像ではなく、登録座標から作る図。もう一度押すと目の前へ置き直す。XRではグリップで図を隠して操作盤を開き、地点を選ぶ。操作盤を閉じると図へ戻る。
- **実寸の地点を見る**：登録したmの間隔で表示。現地に重ねる場合はARへ切り替え、下記の机の位置合わせを各Questで行う。
- **地図を隠す**：表示だけを閉じる。共有した地点・選択先・便は残る。

見方は端末ごと。縮小図に変えても耳や飛行は縮まらない。選んだ地点へ視点を移す／飛行機を向かわせる機能は未実装。6体験の整理は[再設計書](experience-redesign.md)。

## 基盤となる3つの要素

| 体験 | 現在できること |

| 仮想の空 | 既存の共有飛行を、それぞれの頭の位置から見る |

| 会場マッピング | 机を原点に地点名・座標を登録し、PC／XRで配置と選択先を共有する |

## PCでの準備

1. [共有版](https://airplanevoice-shared-sky.tomohaya-falcon-aramaki.workers.dev/?shared=1)で部屋を作る。2台とも同じ部屋を開く。共同操作には編集用URL、観覧だけなら展示部屋の観覧QRを使う。
2. 「机の位置合わせ・会場マップ」を開く。初期値はA–B間60 cm、机の高さ75 cm。実測値に直し「会場の配置を共有に保存」を押す。
3. 固定した水平な机にA・B・Cの印を置く。A→Bが共通の+X、A→Cが共通の−Z。CはAから直角に、A–Bと同じ距離だけ離す。**向かい側に立ってもA/B/Cを入れ替えない。** Cの側が図面上の「奥」。
4. 必要なら仮ブース3地点の名前・X・Zを編集し保存。座標はAを原点としたm単位、各軸±25 mの小さな試作範囲。表示マーカーは机と同じ高さに置く。

水平座標の原点はA、高さの0 mは床。+X／−Zの向きはA/B/Cで決まり、現地の東西南北を自動測定するものではない。

机の大きさに合わせて基準間隔を変更できる（30〜200 cm）。机の高さは40〜140 cm。遠くの機体だけでは位置のずれを見分けにくいので、まず近くのA/B/Cで確認する。

## 各Questで行う位置合わせ

1. 空を開き「見え方・操作案内」→「机と会場」→「机の位置合わせを始める」。AR表示に切り替わり、自分の音が休憩する。他の端末の飛行は続く。
2. **手元に表示される光る玉の中心**を現実のAへ合わせ、トリガー。続けて同じ手でBに合わせてトリガー。コントローラー筐体の先端そのものを基準にしない。
3. 続けて同じ手の玉を現実のCへ合わせ、トリガー。表示されたCのずれを読む。5 cm以内で、表示されたA・B・Cが現実の印にも重なっていれば「重なりを確認」。5 cmを超えた場合や目視でずれた場合は「机の位置合わせを始める」でAからやり直す。向かい側でもCの場所を変えない。
4. 「会場の地点へ」→「地図の見え方」→「実寸の地点を見る」で表示する。編集権限があれば地点の選択を共有できる。観覧者は表示だけを切り替えられる。
5. 「空の操作へ」から「音を聴く」で観察を再開。基準点・地点表示は必要に応じて隠す。ARと仮想の空の往復で校正と便は維持される。

グリップで操作盤を呼び戻す。A/B取得中のグリップは位置合わせを中止する。A/Bの距離・高さが設定と大きく違う場合は、再取得を案内する。縮尺は変更せず、1 mの頭の移動は1 mのまま扱う。

C取得中もグリップで中止できる。「共有・2台の状況」で各端末の報告を確認し、「基準点を見て比べる」で盤を隠して同じ印を見比べる。解除は同じ画面の「自分の位置合わせを解除」。確認中は自分の音が休憩しているので、空の操作へ戻り「音を聴く」で再開する。

AR非対応・AR開始を拒否したセッションでは、この実物との位置合わせは使えない。従来のVR観察は利用できる。

## 共有されるもの／端末ごとのもの

- 部屋で共有・保存: 地点名と座標、選択先、机の高さ、A–B間隔、既存の飛行設定・開始時刻。
- 端末ごと: 頭の位置・視線、校正の回転・移動量、AR／仮想表示、補助マーカーの表示、音量・休憩。
- 保存は既存の部屋の有効期限に従う。恒久的な会場台帳ではない。
- 校正はセッションを終了すると破棄する。再入場、追跡喪失、原点リセット、机の高さ／基準間隔の変更では合わせ直す。追跡の基準が失われた端末は音を休憩し、機体・地点・軌跡を隠して案内を出す。
- QRは入室先を渡す。印刷したQRの3D姿勢を自動で計測する実装は入っていない。
